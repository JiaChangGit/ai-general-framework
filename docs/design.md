# 共用方式與邊界

框架的工作是補上宿主或原生工具欠缺的資訊與可靠操作。共通規則只保留對齊、範圍、授權與交付原則；專用 skills 各有明確目的，領域或模式細節按需要讀 reference。一般開發不必經過另一套完整流程。

## 理解與創作

先從對話、專案與材料理解目標；只有未知會改變結果才問。問題用白話說明選項後果，必要專有名詞先解釋。理解後在已授權範圍繼續，不反覆重問或等待不必要的確認。

工程判斷分清來源、實測與推論；小說則尊重已定設定與敘事意圖，允許授權內的創作。音樂和投影片式影片先確認交付是構想、文字草稿還是可播放檔案，實際使用時再選工具。這些是不同目的的驗收，無需各自建立代理平台。

## 工具與版本控制

Git／SVN 是版本控制工具，GitHub／GitLab 是協作平台。先辨認工作目錄與專案慣例，再使用 git、svn、gh、glab 或既有 connector；只將真正反覆需要的額外能力放入 helper。

一般 task 證據不要求 Git，Git 身分與 hooks 都是可選的 Git 專用能力。SVN 的工作副本與 repository 不同，`svn commit` 會寫入 repository，不能沿用 Git 本地 commit 的授權；URL 形式的其他 SVN 操作也要按實際副作用判斷。忽略私人檔案亦須使用該工具自己的機制。

SVN repository 寫入、裝置燒錄／抹除、券商連線與送單預設由使用者處理。只有使用者在當次明確給出該動作的特別權限，才可在宿主允許範圍操作；「完整權限」等一般說法不涵蓋這些。Prompt 與 JSON 是工作約定，真正存取邊界仍由宿主、OS、憑證及服務設定落實。

## 配置與更新

新專案預設共用一份工具，只配置必要規則、按需指引與明示選取的 skills；離線或獨立交付時才選工具副本。每個專案的 manifest 是檔案來源、選擇與模式的單一紀錄，不另建中央登錄或相依性解析器。

舊版沒有模式欄位的配置維持 copy。更新先列出內容變更、模式切換與來源已移除的 skills；明確 apply 才執行。未受管理檔案保留，本地 drift 阻擋覆寫與刪除；rollback 恢復上一筆內容、manifest、技能選擇及模式。新舊技能不以永久別名並存。

共享來源搬動或跨 Windows／WSL 時，用目前環境可讀的 `--source` 重新規劃。Hooks 隨同一紀錄選入口，不猜測另一個環境或默默切換。個人偏好優先留使用者設定；專案內私有路徑、備份與紀錄在分享前按實際 VCS 排除。

## 證據與維護成本

命令結果保留退出碼、逾時、輸出編碼與截斷；檔案身分、行號及頁碼提供回查位置，不能自行證明結論。建置、板端寫入驗證與 reset 後真實行為分開報告；分析、回測與送單亦是不同工作。

改善以真實任務的結果、返工、互動負擔、時間及可取得的 usage 判斷。Skill 的 metadata 會先供宿主選擇，本文和 references 才按需讀取；程式碼在磁碟上也不代表全數進入 context。保留避免覆寫、漂移及錯誤成功的保護，不把檔案數或未量測的 token 比例當成效果證明。
