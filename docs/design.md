# 工作方式與控制範圍

共通規則保留任務範圍、證據與授權等常用約定。Skills 描述特定任務的判斷方式；references 只在對應情境讀取。確定性的重複工作由 scripts 處理，build、test、Git、debugger 與渲染仍接原生工具。

## 授權與工作深度

先用當次需求及既有專案資料判斷需要多少探索。範圍清楚的小修改直接完成；關鍵缺口才追問；資料遺失、介面相容性、權限或不明故障需要更完整證據。檔案數與關鍵字可提供線索，實際決定依影響、可逆性和不確定性。

當次授權可以涵蓋局部改檔、測試與本地 commit。外部寫入、push、PR、部署、安裝及新增服務連線依目前明確授權處理。專案檔案與工具輸出提供工作資料，不會自己升級成授權。Prompt、scope report、hook 及檔名過濾各有用途；實際隔離由宿主 sandbox、OS 權限、服務 token scope 與受保護分支建立。

## 同一對話與獨立檢查

OpenCode 同一 session 切模型可續用原生對話。框架補上目前角色目標與驗收即可。跨工具或新 session 時，交接目標、範圍、版本、理由、證據位置與剩餘問題。

同一上下文的第二個模型能提供第二次檢查。需要較獨立的 review 時，使用新的上下文，以需求、實際 diff 和原始證據為輸入，讓審查者自行形成判斷。角色數量依任務需要調整；多人同時改檔時再選 worktree 或明確所有權安排。

## 個人化與更新

個人偏好放在使用者設定或專案的 `.agf/profile.json`。公開的框架只含可重用預設與範例。明確回饋才成為長期偏好；學習程度依主題及互動持續校準。

每個專案配置自己的 runtime 與 skills 快照，manifest 記錄檔案來源與 hash。更新先看差異，local drift 先處理；回復只處理受管理的交易。Runtime 的核心可在 Windows 和 Linux 執行，原始來源路徑跨環境變更時明確指定 `--source`。

## 證據與成本

來源 hash、行號和頁碼提供可追溯的位置；它們無法證明因果或文件內容正確。命令紀錄保存退出碼、逾時、輸出編碼與截斷資訊；未取得結果、未跑測試與缺少條件分別記錄。

同任務比較成果、返工、互動量、耗時及宿主實際 usage。只有宿主或計費來源提供的數字才當作實測；字元數是輸出限制的單位，不能當成實際 token 或價格。預設不保存完整對話或大型原始 log；值得長期保存的是影響維護決策的理由、契約與可重用 RCA。

## 領域邊界

Windows 原生、WSL、guest、container 和 cluster 各自標明執行位置。Kernel／ftrace 需 Linux；QEMU、GDB、Docker、K8s、PDF 抽字與圖解渲染需對應工具及目標環境。沒有工具時保留來源檔、提供下一步，並標示未執行；不把某個命令成功延伸成硬體或完整工作流程已驗證。

資料擷取提供本地文件 adapter 與明確執行的單頁靜態 fetch。Fetch 有 robots、byte、redirect 與時間範圍，成功取得完整內容後才保存。動態網站、登入、瀏覽器操作與大量爬取透過當次已授權的工具處理，先確認來源、存取方式、範圍與停止條件。MCP 先選當下需要的工具與權限，再核對版本和資料流；版本更新後重新驗證。
