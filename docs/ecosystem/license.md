# 授權判讀

資料庫每一筆都有一個授權標記。它依原始授權文字判斷，用來決定「要不要再查」，不是法律意見。看不懂或互相矛盾的就標成需要人工確認，不猜。

## 四個標記

判斷的用途是框架平常會做的事：讀它的設計、在本機當外部工具執行、照它的做法自己重寫。要把它的程式碼、文字或素材複製進框架（MIT 授權、公開在 GitHub）時，另看 `license.notes`。

| 標記 | 意思 | 例子 |
|---|---|---|
| 可使用 | 找到明確的授權依據，上面三種用途都沒問題；複製程式碼時保留授權聲明即可 | MIT、BSD、Apache-2.0 |
| 有條件 | 能用，但有會影響做法的條件 | GPL、AGPL（當外部工具執行可以，複製進 MIT 框架不行）；CC BY-NC（不能商用）；ShareAlike；公司規模限制；模型權重另有限制 |
| 需人工確認 | 授權資訊不完整或互相矛盾 | 沒有 LICENSE 檔；README 的 badge 和 LICENSE 不同；不同目錄授權不同、範圍不清 |
| 不建議 | 明確禁止這個用途，或有其他重大風險 | 條款禁止這種使用；要求對使用者資料取得不合理的權利 |

## 要分開看的幾種授權

一個專案常同時有好幾種條款，不能用 repo 的授權代表全部：

- **Repository 授權**：根目錄的 LICENSE、COPYING，或檔案開頭的 SPDX 標頭（例如 `SPDX-License-Identifier: MIT`）。
- **相依套件**：打包或連結進去的函式庫各有授權，GPL 的相依可能影響整體。
- **模型權重**：通常有自己的授權檔或 model card，常見非商用限制。
- **資料集與訓練資料**：dataset card 的授權；資料集本身的授權，不代表裡面每一筆內容的權利。
- **生成結果**：有些服務或模型對產出的使用另有規定。
- **API 與網站的使用條款**：用服務時適用的是服務條款，不是程式的開源授權。
- **圖片、字型、音樂、影片素材**：常和程式碼放在同一個 repo，授權卻不同（[link-study](../link-study.md) 記錄過 Pose Gallery 的程式是 MIT，圖片不是）。

## 怎麼找

1. 讀根目錄與子目錄的 LICENSE、COPYING、NOTICE，以及 README 的授權段落。
2. `gh api repos/OWNER/REPO --jq .license.spdx_id` 是 GitHub 自動偵測的結果，可能偵測錯或寫 `NOASSERTION`，要回去看原文。
3. 要引入外部程式碼或素材時，用 ScanCode Toolkit 或 REUSE 這類工具逐檔掃描（見[資安與授權工具](categories/security-devops.md)）。工具的結果是依據，不是結論。
4. 資料集看 dataset card 與來源網站的條款；模型看 model card 與權重的授權檔。

## 蒐集網頁資料時

可以公開讀到，不代表可以任意蒐集、修改與再利用：

- robots.txt 是網站對爬蟲的要求，要遵守，但它不是授權；授權看網站的使用條款與內容本身的著作權。
- 照網站允許的頻率抓，遇到限制就停，不繞過登入、驗證或付費牆。
- 含個人資料的內容，蒐集、保存與再利用都受個資法限制；研究用途也只取需要的欄位。
- 保留來源網址、抓取時間與當時的條款，之後才查得回來。

## 寫進資料庫

`license` 欄位：`spdx` 寫 SPDX 識別碼（查不到寫 `null`），`basis` 寫依據（哪個檔案、哪個 commit），`label` 寫上面四個之一，`notes` 寫模型、資料集、素材等其他條款與還不確定的地方。
