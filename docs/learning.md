# 用框架學會一件具體的事

先說明想完成的任務、目前背景與卡住的位置。例如：「我會 C，想看懂這個版本的 kernel 如何完成一次檔案讀取；請先帶我走正常路徑，再解釋等待與錯誤。」比「教我 Linux」更容易安排有用的起點。

`guide-learning` 負責調整教學方式，`trace-code` 處理程式與狀態追蹤，`read-research` 處理論文和規格。修 bug 時可接 `debug-root-cause`，準備上游 patch 時再用 `contribute-upstream`。只載入當前需要的能力，不必先跑完整課程流程。

## 怎麼帶讀

| 這次的目的 | 合適的入口 | 可觀察的進展 |
|---|---|---|
| 了解陌生 repo | 用途、執行入口、一個可觸發的行為 | 能定位與該行為相關的程式，解釋一條主要路徑 |
| Trace code | 具體輸入、guard、狀態及 ownership | 能說明狀態為何改變，並找到對應來源 |
| 學新工具 | 一個現在需要的任務 | 能再次執行、解讀輸出、查文件及定位常見失敗 |
| 讀論文 | 問題、貢獻、方法和證據 | 能區分作者證明的內容與未支持的推廣 |
| 讀 spec | 版本、角色、模式、條件及一個情境 | 能沿條文推導結果，指出來源未指定的部分 |
| 準備貢獻 | 可查證的問題與小型邏輯變更 | 具備可審查的 patch、理由及相關驗證；是否接受由上游決定 |

這些是安排與觀察進展的方向，不是每次必填的評分表。框架會依目標、相關先備知識與當下互動調整，不要求使用者先選一種學習法，也不替人貼上「視覺型」等永久分類。

第一次遇到機制時，先示範完整的小情境；逐漸熟悉後減少提示。自我解釋、預測、間隔回顧與相近情境比較可以按需要加入。直接帶讀時保留完整解說，不為了測驗隱藏核心資訊；需要長期記住時，才考慮日後重用與複習。

## 圖、來源和執行證據

圖應回答一個明確問題。角色關係用拓樸，跨元件事件用時序，狀態與條件用狀態圖或流程圖；需要比較欄位時用表。箭頭要能區分一般呼叫、排程、訊息、資料和通知，不能把互斥分支畫成先後執行。

閱讀材料時分清以下內容：

- 由程式或規格支持的靜態解釋。
- 為教學選定的假設值與推演。
- 實際環境、命令、輸入和輸出支持的 runtime 觀察。
- 使用者實際操作或解釋所呈現的理解。

這四項不能互相替代。單一 backtrace 看不到完整非同步歷史；圖能 render 不代表圖意正確；腳本通過也不能證明真人已學會。

## 可以直接試的帶讀情境

[佇列情境](../examples/learning/README.md) 包含無外部相依的 Python 程式、來源追蹤、刻意保留的原子性缺陷，以及修正應維持的條件。它可在 Windows 原生 Python 與 Linux/WSL 使用，操作只影響程序內的記憶體。

[研究閱讀情境](../examples/research/README.md) 使用自製小規格及公開論文閱讀指南，示範如何核對規範強度、guard 順序、主張與證據。自製規格是教材，不代表任何正式產業規格。

可以對代理說：「先完整帶讀佇列案例，使用靜態追蹤標示；等我同意執行後再比較輸出。」也可以說：「我已看過正常路徑，請改用容量不足的情境，先讓我預測，再核對原始碼。」兩種要求都能使用同一份材料。

支援學習方法的研究與它們的適用限制，見 [研究依據](research.md)。本框架尚不能從 AI 的回答推斷真人的長期學習成效。
