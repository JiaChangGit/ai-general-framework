# 安全稽核紀錄

日期：2026-11-08。這份紀錄描述此次實際檢查、重現、修正與剩餘限制；它不是安全認證，也不能保證不存在其他漏洞、錯誤或私人資料。

## 2026-11-09 發布前補充

後續新增可選 `run --max-output-bytes`，對 stdout／stderr 合計保存量設上限，超限停止並回報失敗；本框架品質設定也採用此上限。未指定時仍維持下述完整暫存行為。這不是磁碟或程序沙箱，Windows 父程序先退出時的後代清理仍有限制；參數與證據語意見 [CLI](cli.md)。另已用隔離固定版 Gitleaks 執行追蹤檔案與 Git 歷史掃描，結果與工具範圍見最新[驗證紀錄](verification.md)；下列早期有限規則掃描保留為歷史證據。

以當時本機 `main` 和 `origin/main` 兩個 refs 的 12 個提交、257 個相異 blob，以及提交訊息和工作目錄待發布內容，使用有限規則搜尋常見私鑰、服務權杖、URL 使用者資訊、部分憑證檔名、電子郵件和個人家目錄等；未發現疑似真實秘密。匹配到的資料屬測試值、保留網域或通用路徑示例。未安裝第三方掃描器，也沒有驗證憑證是否有效；掃描無法辨識所有機密、個資、編碼和其他未納入的 refs。作者名稱及 noreply 郵件地址仍會隨提交公開，使用者應確認。

- 原本的 Dockerfile 使用 `COPY .`，而 `templates/dockerignore` 不會自動生效，可能將本機資料送到 builder 或複製進 image。改為專屬忽略檔和最小來源複製；Compose 也改正相對路徑並限縮唯讀掛載。允許的 Python 來源仍可能包含秘密，須人工檢查；Docker daemon 無法使用，未驗證實際 build 或容器執行。
- 合法 UTF-8 檔名若包含 U+FFFD，原先會被誤認為解碼失敗。改以實際解碼錯誤旗標判斷，並以真實 Git 檔名檢查合法字元和非法位元組的區別。
- `run --max-chars` 限制回傳摘要，並不限制原始輸出暫存；大量輸出仍可能耗盡磁碟。已在 [CLI 操作](cli.md)說明使用邊界，未改變其完整暫存行為。

WSL 在修正後執行 190 項單元測試，2 項跳過；Windows 在修改前執行 188 項，15 項跳過，修正後另執行受影響的 Git 與 integration 測試。Windows Compose config 已核對掛載路徑；詳細限制見下方與 CLI 文件。以下原紀錄保留 2026-11-08 當時狀態，包含當時尚未設定 remote 的敘述。

## 檢查範圍

以本機程式和隔離測試資料檢查批次檔案操作、來源讀取及比對、Git 交接紀錄、配置與回復；網頁相關測試只使用本機測試服務。另檢視受管理規則、工具授權及 CI 設定。測試沒有連接真實券商、操作硬體、寫入遠端或修改其他專案。

隱私檢查涵蓋本機所有可到達 Git refs 所指向的提交、其中的相異檔案內容、提交訊息，以及目前追蹤與未忽略的新檔；以本機有限規則搜尋常見私鑰、雲端與服務權杖、部分固定格式的秘密及個人家目錄路徑。掃描只記錄規則與檔案位置，不印出疑似秘密。另檢查遠端網址是否有 HTTP 使用者資訊，不輸出網址；此次沒有設定 Git remote。忽略中的 `.agf/`、憑證及其他私人檔案不屬於將要提交的內容，也不在本次公開檔案掃描範圍。

這不是完整個資辨識：不認得所有秘密格式、編碼或分割後的秘密，也不能識別所有姓名、地址、帳戶或機密業務資料。未安裝或執行第三方安全掃描器，沒有驗證任何憑證有效性。準備發布時仍要查看差異、檔案清單、作者資訊及實際要推送的 refs；忽略規則不能移除已追蹤或歷史中的資料，強制加入也可繞過忽略。

## 已重現並修正

| 問題與影響 | 修正與驗證 |
|---|---|
| POSIX 批次改名／正規化期間，原為 `0600` 的私有檔案可能暫時以 `0644` 建立；可遍歷目錄的其他本機使用者可能在寫入期間讀取 | 先以 `0600` 獨占建立，再寫入內容，完成後恢復來源權限。以合成資料觀察改名與正規化時的寫入權限，並測試建立失敗的還原。Windows 的 ACL（存取控制清單）需另以該環境驗證。 |
| Git 狀態含無法以 UTF-8 解碼的檔名時，不同名稱可能變成相同替代字元，交接紀錄因而誤判狀態未變 | 無法可靠解碼時停止建立狀態識別，不把替代字元的雜湊當證據；以不同的 POSIX byte 檔名驗證拒絕。 |
| Git 的 diff 文字轉換（textconv）可能執行已在目標工作目錄設定的外部程式，即使任務只是記錄狀態 | 本框架執行 Git diff 時停用 textconv 與 external diff。以配置了合成轉換程式的隔離 repo 驗證它不再被呼叫；這不涵蓋下方說明的其他 Git filters。 |
| 大量短行或 HTML 片段可在有限位元組內產生大量物件，導致本機記憶體耗盡 | 文字行數、HTML 文字單位、PDF 選頁及抽取字元設有上限；超限明確報錯。合成 10 萬換行情境從建立大量物件改為事前拒絕；PDF 解析器本身不受沙箱隔離。 |
| 重複行的 `source diff` 可能在回傳有限輸出前耗用大量 CPU | 正規化後相同時直接回傳；不同時設定比較單位及工作量上限，超限明確要求縮小範圍，不假稱結果完整。 |
| 更新或回復受管理檔案期間，另一程序的修改可能發生在預先檢查之後而遭覆寫 | 套用及回復時重新核對各個目的檔，安全回復不可能時保留競爭者的內容並回報快照位置；這只能縮小競態，無法將核對和替換變成跨程序原子操作。 |
| 更新受管理檔案時，原本私有的檔案及替換暫存檔可能以較寬鬆的 POSIX mode 建立；暫存檔撞名時，舊的失敗清理也可能移除別人的檔案 | 替換暫存檔先以 `0600` 獨占建立、寫入後保留原檔 mode；只清理本次成功建立的暫存檔。以合成私有檔、撞名及故障注入驗證；Windows ACL 仍待相應平台的權限驗證。 |

新建立的 `.agf/` 與 history 目錄在 POSIX 以 `0700` 建立，新建的 `.agf/` 受管理檔案及歷史快照以 `0600` 建立，以保護其中可能含本機路徑和舊內容的紀錄；既有目錄及檔案的權限不會由工具擅自變更。Windows 的實際存取控制與既有目錄權限仍需依環境檢查。

## 使用與剩餘邊界

- `run` 明確執行使用者給的程式；輸出、命令參數與可選原始紀錄可能包含敏感資料。`source fetch` 的網址與重新導向資訊可能包含查詢參數。工具不自動遮罩秘密，分享前應檢查。參考 [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)。
- 本框架的文字規則、預覽與 hooks 不是作業系統的 sandbox。外部文件和工具回傳都屬於不可信資料，不能擴張任務授權或索取秘密。
- `git summary/scope` 與 `task record --repo` 仍呼叫本機 Git；Git 依現有配置可能執行 clean filter 等外部程式。曾以隔離合成 repo 實際確認此行為；停用 textconv 不能防止所有 Git 擴充程式執行。對不可信的工作目錄或 Git 設定，應先審查並使用適當的系統隔離，不把這些命令當成安全沙箱。
- `source fetch` 可依使用者指定網址連線，包括本機或內網位址；重新導向限制和 robots 檢查不是內網存取控制。不要讓不可信文件自行指定要抓取的網址，需由已授權的任務決定目的地並依環境限制網路。
- 沒有證明同目錄遭惡意程序並行操作時完全沒有競態；不要把這些工具當作多租戶或不可信程序之間的檔案隔離邊界。
- 可選 PDF、渲染器、MCP 與 host 本身的弱點、依賴版本、硬體、線上 CI／服務與各種平台權限未全面驗證；按當次任務審查其來源與資料流。
- 掃描結果是特定時點和規則的觀察，不是「已保證沒有秘密」。即使平台有自動阻擋，也有其[支援範圍和限制](https://docs.github.com/en/code-security/reference/secret-security/secret-scanning-scope)。
