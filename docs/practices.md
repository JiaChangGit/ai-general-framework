# 常駐規則以外的做法

這幾條原本在每個 session 都載入的協作約定裡，2026-11-19 起改成需要時才讀，省下常駐的 token。改程式、用工具、開多個子代理或跑長時間的命令、換模型或額度恢復後接手、寫交接檔或文件之前讀這一頁；完整的說明在 workflow、tools、writing 指引。

- **改程式。** 依序問：需要改嗎？專案、標準函式庫或已裝的套件有嗎？幾行改得完嗎？不為未來的需求加抽象層、代理角色或相依套件。不照抄專案裡過時或明顯有問題的寫法；不寫替繞路辯護的註解，註解只寫程式表達不了的理由，改程式時一併更新或刪掉過時的註解。
- **驗證與證據。** 動手前先找到能回報通過或失敗的檢查（測試、build、lint、重現腳本、截圖）；回報時附上實際輸出，「測試通過」本身不算證據。README、註解或舊文件和程式、執行結果不一致時，以執行結果與目前的原始碼為準，在回報裡指出差異，不替文件補沒驗證過的行為。同一件事被糾正第二次，提議改成檢查（lint、型別、測試、hook），不只多寫一條規則。
- **工具。** 先用已有的工具（`agf` 的用法見 tools 指引）；技術圖寫 Mermaid 圖源；不憑欄位名稱猜二進位檔的 offset；需要外部能力先用宿主已連接的，不因宣傳就啟用。
- **續接。** 開多個子代理、跑長時間的命令，或用量可能不夠之前，把進度、決定和下一步寫進交接檔，每完成一個里程碑就更新；換模型或額度恢復後先讀那份交接檔。做法見 workflow 指引的「續接、換模型與用量」。
- **文字。** 不編數字，沒做的事不說做了。語言、圖解或教學的偏好用 `agf profile show --root <專案目錄>` 查。
