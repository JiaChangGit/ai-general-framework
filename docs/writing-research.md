# 本輪寫作規則的依據與驗收

本頁供框架維護者回查來源；下游日常寫作使用 [writing.md](writing.md)，不用每次重讀研究。查閱日期為 2026-11-09；以下核對兩篇 v1 原文，沒有重跑作者的實驗。

[Clark、Martin 與 Mahowald，Why is AI-generated language so hard to understand?](https://arxiv.org/html/2610.29162v1) 的第 3 節比較英文模型輸出、往返翻譯及可取得的人類語料，觀察罕見搭配、長距依存、名詞堆疊等特徵；不同模型與情境有差異。第 4 節用小模型展示長度懲罰可能改變句法偏好，不能據此確定所有商用模型的訓練成因。第 7 節明列只分析英文，這不是台灣中文規則的實驗驗證，也沒有證明每個被列出的句子都難懂。

[Cekini 等人，The Cognitive Cost of LLM Writing: A Reading-Time Comparison with Human Text](https://arxiv.org/html/2610.23715v1) 的第 III 至 V 節使用眼動資料訓練的 RoBERTa-RT，比較 496 篇英文新聞及單一模型的改寫。改寫的預測總閱讀時間略短，每詞預測時間較長；第 VI 節指出，這批配對文本沒有直接的人類眼動量測，仍需真人研究確認理解與認知負擔。結果不能外推成所有模型、中文或單篇文件的實測閱讀時間。

因此，本輪採用「別只靠縮短篇幅判斷好讀」與「檢查不自然搭配、過長修飾及不明動作」作為校閱線索。台灣中文的話題延續、人稱指涉、語序與習慣搭配，則是依使用者要求採用的編輯選擇；「流暢性陷阱」在此指讀起來順卻缺少具體內容，不宣稱是兩篇論文已驗證的同一研究構念。這些線索都不作 AI 作者偵測或機械退件條件。

[writing-cases.json](../evals/writing-cases.json) 提供可直接交給代理的材料及語意條件。另開對話時只提供 `request`、`facts`、`draft`，審查者保留 `preserve`、`observe`、`avoid`，避免代理照抄驗收答案。固定 host、model、版本及原始材料，比較改動前後；先判斷事實是否保留，再看能否直接回答「誰做什麼、什麼條件、結果如何」。可接受多種寫法，不以與參考句相似度打分。

驗收含刻意清楚的反例，以及不得增補的未知。字詞計數、JSON 語法與框架 audit 只驗證材料結構；代理自評與少量試答也不能證明真人理解提升。要宣稱實際可讀性改善，仍須由目標讀者閱讀、回答內容問題，記錄歧義與誤解；要宣稱省 token，另記宿主的實際 usage，包含重試與返工。
