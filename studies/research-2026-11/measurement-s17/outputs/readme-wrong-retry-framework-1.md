程式碼和 README、docstring 的說法不一致，以程式碼為準（`retry.py:3-15`，我只讀了程式碼，沒有執行）。

- **嘗試次數：** `MAX_ATTEMPTS = 3`，所以總共嘗試 3 次，不是 README 說的「重試 5 次」。
- **等待時間：** 每次失敗後睡 `delay * (attempt + 1)`，預設 `delay=0.1`，依序是 0.1、0.2、0.3 秒。這是線性增加，不是指數退避。第 3 次失敗後也會再睡 0.3 秒才結束。
- **最後結果：** 3 次都丟出 `ConnectionError` 時，會 `raise last_error`，也就是重新丟出最後一次的例外，不會回傳 `None`。其他類型的例外不會被捕捉，會立刻往外丟。

README 和 docstring 都寫了「5 次、指數退避、回傳 `None`」，和實際行為不符。呼叫端如果照 README 不寫 try，就會漏接例外。我沒有改檔案；要不要修正文件或程式碼，請你決定。
