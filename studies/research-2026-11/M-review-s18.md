Reviewed from `git archive fad222f` in a scratch copy. Tests in the copy: 343 run, OK, 8 skipped. `test_published_files` skips there because the archive has no `.git`. Probes ran in throwaway repositories (git 2.53, Python 3.14, Linux). Nothing was measured or paid for.

## 1. Code

**R1 (bug) `agf/traces.py:25-26` commit-msg regex, false positives and negatives.**
Reproduced with `git commit` through the installed hook:
- Blocked, but it is a person or a plain phrase: `Co-authored-by: Jane Claude <jane@x.org>`; subject `feat: cursor position generated with cursor offset`; `docs: note about generated by Codex style`; `Generated by GPT-style tokenizer fix`.
- Not blocked, but it is a tool: `Co-Authored-By: Gemini <g@google.com>`. Only "gemini code assist" is in `AUTHORS`, while `TOOLS` has `gemini`, so the two lists disagree.
- `\b` after a name matches "claude-code" and "cursor-position".
- The `generated with/by <tool>` alternative has no line anchor, so ordinary prose in a subject or body hits.
- Fix: anchor `generated ...` to a line start or a trailer or footer position. Require the `<...@...>` form or a known tool address for `co-authored-by`. Share one list between the hook and `check`.
- `FILE_MARKERS` (line 29) only knows Claude, so `check` and the hook disagree about what a trace is.

**R2 (risk) `agf/traces.py:114-116,142` `core.hooksPath` is followed blindly.**
- Reproduced: with `core.hooksPath` set to a shared directory, `traces hook --apply` writes `commit-msg` into that shared directory. It then affects every repository using it. `--remove` deletes it for all of them.
- With a relative `hooksPath` such as `.githooks`, the hook lands inside the work tree. It is not covered by the exclude block, and its text names "agf traces". `git add .` would publish it, which defeats the no-trace goal.
- The write follows a symlinked `.git/hooks/commit-msg`: a dangling symlink makes `is_file()` false, so the target was created.
- Fix: if `core.hooksPath` is set, report `FOREIGN_HOOKS_PATH` and do nothing unless the path is under `.git`. Use `os.path.lexists` and refuse symlinks.

**R3 (risk, not reproduced) `agf/traces.py:33` Windows interpreter lookup.**
- `command -v python3` finds the Microsoft Store stub in Git Bash. The stub exits non-zero, so `exec` makes every commit fail, which contradicts the "do not block" comment on line 34.
- A Python 2 `python` would also fail on `errors=`.
- Fix: probe with `"$PY" -c "import sys; sys.exit(0)"` before `exec`. Fall through to `exit 0` on failure.
- CHANGELOG says "Git for Windows 上真的 commit 測過". The hook was not run on Windows here, so that claim is unchecked.

**R4 (nit) `agf/traces.py:133`.** `--remove` deletes any file containing the marker, including one the user edited. Compare against `_hook_text()` before unlinking.

Checked, fine for `traces.py`: `commit -v` (diff after the scissors line) does not trigger the hook; worktrees (`--git-path` resolves to the common dir); a foreign hook is left alone; the exclude block with CRLF.

**R5 (bug) `templates/claude-guard-hook.py:94,472-498` MCP write detection regressed.**
- Whole-word matching uses `[A-Z]?[a-z0-9]+`, so a lowercase compound is one word.
- Reproduced with a protected `path` argument: `mcp__fs__write_file` and `mcp__fs__WriteFile` exit 2, but `mcp__fs__writefile` and `mcp__fs__createfile` exit 0. The old substring regex caught these.
- Fix: also test word prefixes or suffixes (`writefile`, `editfile`, `createfile`). Or invert the rule and refuse unknown tools that carry a protected path, unless the name matches a read-only word list.

**R6 (risk) `templates/claude-guard-hook.py:478`.**
- `depth > 6` silently stops scanning. Reproduced: `{"a":{"b":{"c":{"d":{"e":{"f":{"g":{"command":"git push"}}}}}}}}` exits 0.
- It is a known-limit class, but it is not documented. Fix: refuse, or at least say so in the header, when the limit is hit.

Checked, fine for `check_mcp`: nested `command`, sibling `args`, `commands` lists, `source`/`destination` pairs, `file://` paths, and a relative path with an absolute `cwd` (all exit 2).

**R7 (risk) `evals/host/impact.py:236-237` and `evals/host/run_claude.py:23,44-45`, what a measured subject can reach.**
- Subject and reviewer run with `--allowedTools "Read Grep Glob Edit Write Skill"`. These are blanket rules with no path scope, and `HOME` is kept in the environment.
- `outside_paths` is recorded only after the fact. Preflight runs once, before the subject. Neither the reviewer session nor the second part of a multi-part task is re-checked.
- Write or Edit to any host path such as shell startup files, `~/.claude/*`, or another group's files is therefore possible. `Read` can reach any file.
- The reviewer starts in the same directory the subject just wrote. If the subject wrote `.claude/settings.json` with a hook, a headless session in that directory would load and run it. This is the only route from "model output" to "code executing on the host" in this design.
- The committed runs show no outside paths (checked: 0 in all 56 rows), so nothing happened. The exposure is in the design.
- Fix:
  - Add `--disallowedTools "Write(//**)" "Edit(//**)"` plus an allow rule limited to the work directory.
  - Re-run `preflight.check` before the review session, and fail on any new `.claude/` or `.agents/` entry.
  - Run in a container or a throwaway user.

**R8 (risk) `evals/host/impact.py` reviewed group and merging.**
- The reviewer gets only `task["parts"][-1]["prompt"]` and the last answer (line 235). For a multi-part task it never sees the earlier parts (`decision-only-in-chat`). L-s18 admits this.
- `summarize_runs` takes `last = row["parts"][-1]`, which for D is the review part. `median_last_part_tokens` therefore means different things in different groups.
- `combine` (~line 312) never checks that a row for the same (task, group, repeat) is unique. `framework` rows from `measurement-s18-old2` (the S17 framework, from main) and from the S18 dirs merge into one `framework` cell. `framework_commit` is `35e6b34` in both, but the content is not identical (S18 was measured on an uncommitted tree). An unlabeled merge would report 9 "framework" rewrite runs of three different guides. L-s18 separates them by hand; `impact report` does not.
- `SAME_SETUP` skips a key missing on one side, so a file without `review_model` merges silently.
- Fix: add a `variant` label to the row or the group name, and fail on duplicate keys.

**R9 (risk) `tests/test_published_files.py:13-20`, what could still be committed.**
- The rule is `studies/**/streams/` by directory, or a `.jsonl`/`.json` under `studies/` containing a `session_id` UUID.
- Missed: `.stderr` and `.meta.json` written by `run_claude.py` (the meta file holds `cwd`, `argv`, `env_names`) if they are copied out of a directory not named `streams`. Anything outside `studies/` (for example `evals/` or `docs/`). Raw streams that use a different key.
- The test also skips outside a Git checkout, so it never ran on the archive.
- Fix: scan the entire tracked tree, match `.stderr`, `.meta.json` and any file with `"type":"system"` and `"subtype":"init"`, and add a home-path pattern.

**R10 (doc error / nit) `agf/doccheck.py:94`.**
