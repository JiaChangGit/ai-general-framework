## 追程式的三個問題

追程式時只問三件事,不要逐行翻譯:

1. **入口:** 哪個函式被呼叫,收到什麼值?
2. **條件(guard):** 哪個 `if` 決定程式往哪條路走?
3. **狀態:** 哪些資料會被改?哪些不會?

## 示範:`enqueue(['a'], 'b', 1)`

原始碼(`queue.py`):

```python
def enqueue(queue, job, capacity):
    if len(queue) >= capacity:
        return 'full'
    queue.append(job)
    return 'ok'
```

**1. 入口。** 呼叫時三個參數是 `queue=['a']`、`job='b'`、`capacity=1`。先把進場前的狀態寫下來:佇列內容是 `['a']`,長度是 1。

**2. 條件。** 第 2 行是 `len(queue) >= capacity`,代入就是 `1 >= 1`。`>=` 包含「等於」,所以結果是 `True`。這裡最容易看錯:佇列剛好裝滿時也算滿。

**3. 走哪條路。** 條件為 `True`,進入 `if` 內部,執行第 3 行 `return 'full'`,函式在這裡結束。第 4 行 `queue.append(job)` 和第 5 行都不會執行。

**4. 狀態。** 因為 `append` 沒跑,`queue` 沒有任何改變。

| 步驟 | `len(queue)` | 條件 `len >= capacity` | 執行的行 | `queue` |
|---|---|---|---|---|
| 進場 | 1 | – | – | `['a']` |
| 判斷 | 1 | `1 >= 1` → True | 第 2 行 | `['a']` |
| 離開 | 1 | – | 第 3 行 `return 'full'` | `['a']` |

結論是回傳 `'full'`,而 `'b'` 沒有被放進去。

**這題的重點:**
- 回傳值和狀態是兩件事。回傳 `'full'` 只是告訴呼叫者結果。
- `append` 是直接修改傳進來的那個清單(原地修改),不會另外複製。呼叫者手上的 `['a']` 就是被改的那一個。這題因為走了 `return 'full'`,所以沒被改。要判斷「清單有沒有變」,就看 `append` 那行有沒有被執行到。
