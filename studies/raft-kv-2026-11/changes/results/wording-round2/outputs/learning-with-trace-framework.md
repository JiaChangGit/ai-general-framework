# 從入口、條件、狀態追程式

這裡只依 `queue.py` 與 `input.md` 的原始碼和輸入做靜態追蹤，沒有執行程式。

## 三個問題

追任何程式，都先問這三件事：

1. **入口**：從哪個函式、帶著什麼值開始？
2. **條件**：每個 `if` 在這組值下是真還是假？走哪一條路？
3. **狀態**：哪些變數在途中被改變？回傳時各是什麼？

## 示範：`enqueue(['a'], 'b', 1)`

程式只有五行：

```python
def enqueue(queue, job, capacity):
    if len(queue) >= capacity:
        return 'full'
    queue.append(job)
    return 'ok'
```

**入口。** 呼叫 `enqueue` 時，三個參數是 `queue=['a']`、`job='b'`、`capacity=1`。進入函式前，先把這組值寫成「狀態表」的第一列：

| 步驟 | 行 | queue | 說明 |
|---|---|---|---|
| 進入 | 1 | `['a']` | 參數綁定，尚未做任何事 |

**條件。** 第 2 行先檢查 `len(queue) >= capacity`。`len(['a'])` 是 1，`capacity` 也是 1，所以 `1 >= 1` 為真。注意這裡是 `>=`：容量剛好用完，也算滿。

**走哪條路。** 條件為真，執行第 3 行 `return 'full'`，函式在這裡結束。第 4 行 `queue.append(job)` 和第 5 行 `return 'ok'` 都沒有執行。

| 步驟 | 行 | queue | 說明 |
|---|---|---|---|
| 判斷 | 2 | `['a']` | `1 >= 1` 為真 |
| 回傳 | 3 | `['a']` | 回傳 `'full'` |

**狀態結果。** 回傳值是 `'full'`，`queue` 仍是 `['a']`，`'b'` 沒有被加入。唯一改動 `queue` 的是第 4 行，而這次它被第 3 行的 `return` 擋在前面。

用狀態的角度看，這支程式有一個規律：拒絕時不改動任何東西。

## 練習

呼叫改成 `capacity=2`，並連續呼叫兩次，兩次用同一個清單：

```python
q = ['a']
r1 = enqueue(q, 'b', 2)
r2 = enqueue(q, 'c', 2)
```

問題：`r1`、`r2` 各是什麼？最後 `q` 是什麼？

## 核對方式

先不要看答案，照示範畫狀態表，每次呼叫各一張，並寫下 `queue` 在每一步的內容。再依序檢查：

1. 第二次呼叫開始時，`q` 是第一次呼叫結束後的值，還是原本的 `['a']`？函式用 `append` 直接改清單，沒有複製，所以呼叫者手上的 `q` 會跟著變。
2. 每次呼叫的第 2 行，`len(queue)` 與 `capacity` 各是多少？比較結果為真還是假？
3. 走到第 4 行的那一次，`queue` 才會多一個元素；走到第 3 行的那一次，`queue` 不變。

**參考答案。**

- **第一次：** `len(['a'])` 是 1，`1 >= 2` 為假。程式執行 `append('b')`，`q` 變成 `['a', 'b']`，回傳 `'ok'`。
- **第二次：** `len(['a', 'b'])` 是 2，`2 >= 2` 為真。程式回傳 `'full'`，`q` 不變。
- **結果：** `r1 == 'ok'`、`r2 == 'full'`，最後 `q == ['a', 'b']`。

若你的答案不同，找出狀態表中第一個和參考答案分歧的步驟。多半是漏了第一次呼叫改動了 `q`，或把 `>=` 當成 `>`。
