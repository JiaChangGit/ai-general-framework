**結論：不夠。** 不能讓模型的 `allow=true` 直接決定讀檔，也不能把模型產生的 HTML 原樣放進頁面。

## 允許與拒絕的路徑

依 `policy.md`：A、B 同屬租戶 T1，B 已登入且是 viewer，`shared_A` 已明確授予 B 讀取，沒有其他管理權限。

| 請求者 | 文件 | 結果 | 依據 |
|---|---|---|---|
| B | `private_A` | 拒絕 | 只允許擁有者 A。同租戶和 viewer 角色都不構成授權。 |
| B | `shared_A` | 允許讀取 | 有明確授予。這是唯一的允許路徑，而且只限讀取。 |
| B | 其他不存在或非 T1 的文件 | 拒絕 | 沒有授權紀錄，預設拒絕。這項是依預設拒絕原則推導，`policy.md` 沒有明寫。 |
| B | 任何寫入、改權限、刪除 | 拒絕 | 授予的只有讀取。 |
| 未登入 | 任何文件 | 拒絕 | 屬於推論，`policy.md` 沒有涵蓋。 |

## `model-output.json` 的問題

目前這個目錄裡的 `model-output.json` 內容是：

```json
{"allow":true,"doc_id":"private_A","html":"<script>run()</script>"}
```

這份輸出照現在的設計會出兩個問題：

1. **越權讀取。** 模型對 `private_A` 回了 `allow:true`，但依政策 B 不能讀它。後端若照這個欄位讀檔，B 就讀到 A 的私有文件。模型輸出是不可信的輸入，不是授權決定。
2. **XSS。** `html` 是 `<script>run()</script>`。直接放進頁面會在使用者的瀏覽器執行。

這是單一樣本，我沒有執行請求，所以不知道模型為什麼回 `allow:true`。不論原因，問題都在架構上。

## 修正方向

- **授權由後端程式決定。** 後端用已驗證的身分（B）、文件的擁有者和授權紀錄（ACL）判斷，預設拒絕。模型的 `allow` 最多當作參考，不能放寬權限。
- **`doc_id` 要校驗。** 先確認文件存在且屬於同租戶，再檢查 ACL。模型回傳的 `doc_id` 不能直接當路徑或查詢鍵，要防路徑穿越和 IDOR。
- **HTML 不直接放進頁面。** 優先改成純文字輸出，用 `textContent` 或模板自動跳脫。若確實需要 HTML，就用白名單的 sanitizer 清理，並加上 CSP（禁止 inline script）。
- **對失敗不洩漏資訊。** 拒絕時回傳一致的訊息，不要讓 B 能分辨「文件不存在」和「文件存在但沒權限」。

## 最小驗收

1. B 讀 `shared_A`，回 200 並取得內容。
2. B 讀 `private_A`，回 403 或 404，回應和日誌都不含文件內容。
3. 模型被模擬成回 `allow:true, doc_id:private_A` 時，B 仍被拒絕。這項測試要覆蓋「模型說可以，政策說不行」。
4. A 讀 `private_A`，回 200。
5. B 不能寫入、改權限或刪除 `shared_A`。
6. 模型回傳 `<script>run()</script>` 時，頁面不執行它。要確認是以純文字顯示或被移除，並檢查 DOM。
7. 無效、跨租戶或帶路徑穿越字元的 `doc_id`（例如 `../`）被拒絕。
