# 用入口、條件、狀態追程式

## 三個問題

追程式時，每一步只問這三件事：

1. **入口**：函式從哪裡被呼叫？收到哪些值？
2. **條件**：哪個 `if` 決定走哪條路？這次判斷是真還是假？
3. **狀態**：哪些東西會被改變（這裡是 `queue`）？哪些沒被改到？

## 示範：`queue=['a']`、`job='b'`、`capacity=1`

原始碼（`queue.py`）：

```python
def enqueue(queue, job, capacity):
    if len(queue) >= capacity:
        return 'full'
    queue.append(job)
    return 'ok'
```

**入口。** 呼叫 `enqueue(['a'], 'b', 1)` 後，函式內的 `queue` 是 `['a']`，`job` 是 `'b'`，`capacity` 是 `1`。

**條件。** 第 2 行要判斷 `len(queue) >= capacity`。
- `len(['a'])` 是 1。
- `1 >= 1` 成立（等於也算），所以結果是 `True`。
- 進入 `if` 內部，執行第 3 行 `return 'full'`。函式在這裡結束。

**狀態。** 第 4 行 `queue.append(job)` 和第 5 行 `return 'ok'` 都沒有執行。所以：
- 回傳值是 `'full'`。
- `queue` 仍是 `['a']`，`'b'` 沒有加進去。

用下表整理這次的追蹤：

| 步驟 | 行 | 判斷或動作 | `queue` | 回傳 |
|---|---|---|---|---|
| 進入 | 1 | 收到參數 | `['a']` | — |
| 條件 | 2 | `1 >= 1` 為真 | `['a']` | — |
| 結束 | 3 | 直接回傳 | `['a']` | `'full'` |

**常見誤解：** 很多人以為要「超過」容量才算滿，也就是 `>`。程式寫的是 `>=`，所以佇列剛好裝滿時，就已經拒收新工作。這個判斷只有在代入具體數字時才看得出來。

## 小練習

輸入：`queue=[]`、`job='x'`、`capacity=0`。

請先不看答案，依序寫出：
1. 第 2 行的 `len(queue)` 是多少？條件為真還是假？
2. 走到第 3 行，還是第 4、5 行？
3. 函式結束時，回傳值是什麼？`queue` 是什麼？

## 核對方式

先自己寫下答案，再對照下面三項。我沒有執行程式，這是依原始碼推出的結果。

- 條件：`0 >= 0` 為真。
- 路徑：走第 3 行，第 4、5 行不執行。
- 結果：回傳 `'full'`，`queue` 仍是 `[]`。

答錯時，先看是哪一項不同：
- 條件判斷錯：多半是把 `>=` 當成 `>`。
- 路徑對、`queue` 錯：多半是忘了 `return` 會讓函式立刻結束。

答對後可以再試一題：把 `capacity` 改成 1，其他不變。條件、路徑和結果會怎麼變？
