**結論：不能。** `cleaned.md` 只保留了 A 類情境，B 類情境整條被刪掉，所以它無法用來概括「兩種情境」。

**證據**

| 項目 | 實讀內容 | 來源 |
|---|---|---|
| 原稿 `original-v2.txt` 第 2 行 | 忙碌時先檢查工作種類與授權，**A 類**工作應**拒絕**請求 | 實讀 |
| 原稿第 3 行 | 同樣前綴，**B 類**工作應**暫存**請求 | 實讀 |
| 清理稿 `cleaned.md` 第 2 行 | 只剩 A 類，B 類不見了 | 實讀 |
| `conversion-note.txt` | 「轉換器把相同前綴的段落當重複，只留下第一筆」 | 實讀 |

**成因（推論）：** 兩句前半相同，只有 A/B 類與後果不同。轉換器依前綴去重，把 B 類誤當重複刪掉。這和說明檔的描述一致，但我沒有重跑轉換器驗證。

**缺項**
1. **B 類情境缺失。**「應暫存請求」這個結果在清理稿裡沒有。
2. **來源資訊不足。** 清理稿第 1 行只寫「來源宣稱為 Spec v2」，沒有 hash、頁碼、章節或版本對照。原稿也只有「Spec v2」一行標頭，沒有 errata 或日期，所以我無法確認這是哪一份正式文件。
3. **不能補全部情境。** 這兩行是否就是該節的全部內容，兩份檔案都看不出來。A、B 以外的類別，以及其他忙碌狀態下的行為，來源沒有說明。依 `specifications.md` 的原則，來源未指定的結果要說「未指定」，不能補成固定行為。
4. **規範強度要保留。**「必須先檢查」是義務（MUST 級），「應拒絕」「應暫存」是 SHOULD 級。清理稿若要改寫成摘要，不能把「應」寫成「必須」。

**目前能做的最多只是**：以原稿為準，才能說「忙碌時，控制器必須先檢查工作種類與授權；A 類應拒絕，B 類應暫存」。這句話的依據是 `original-v2.txt`，不是 `cleaned.md`。建議先修正轉換器的去重規則（只比對前綴會誤刪），再重新產生清理稿。
