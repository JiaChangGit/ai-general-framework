# 用入口、條件和狀態追程式

這份說明只讀了 `queue.py` 和 `input.md`，沒有執行任何東西。下面的結果都是從原始碼推出來的靜態追蹤，輸入是 `input.md` 指定的。

## 三個問題

追程式時，每一步只問三件事：

1. **入口：** 程式從哪裡開始，收到什麼值？
2. **條件：** 遇到 `if` 時，這次的值讓條件成立還是不成立？走了哪一條路？
3. **狀態：** 哪些資料被改了？改完是什麼？

這段程式只有一個入口 `enqueue(queue, job, capacity)`。條件是第 2 行的 `if`。狀態是 `queue` 這個清單，它只在第 4 行的 `queue.append(job)` 被改動。

## 示範：`queue=['a']`、`job='b'`、`capacity=1`

**入口（參數）：**

| 參數 | 這次的值 |
|---|---|
| `queue` | `['a']`，目前有 1 個工作 |
| `job` | `'b'`，要加入的工作 |
| `capacity` | `1`，最多容納 1 個 |

**逐步執行：**

| 步驟 | 程式 | 這次的值 | 結果 |
|---|---|---|---|
| 1 | 第 2 行 `len(queue) >= capacity` | `len(['a'])` 是 1，`1 >= 1` | 成立 |
| 2 | 第 3 行 `return 'full'` | | 函式在這裡結束 |
| 3 | 第 4、5 行 | | 沒有執行 |

**狀態：** `queue.append(job)` 在第 4 行，函式在第 3 行就已經返回，所以 `append` 沒被呼叫。`queue` 維持 `['a']`，`'b'` 沒有進去。回傳值是 `'full'`。

**容易錯的地方：** 條件是 `>=`，不是 `>`。容量 1 的佇列裝了 1 個就算滿，所以這次被擋下。若誤讀成 `>`，`1 > 1` 不成立，就會讓 `'b'` 進去，答案整個不同。追的時候要照符號算，別憑「感覺還有空間」判斷。

## 小練習

連續呼叫兩次，用的是同一個清單：

```python
q = ['a', 'b']
r1 = enqueue(q, 'c', 3)
r2 = enqueue(q, 'd', 3)
```

請寫出：

1. `r1` 和 `r2` 各是什麼？
2. 兩次呼叫後，`q` 是什麼？
3. 第二次呼叫時，第 2 行的比較是哪兩個數字？

建議照示範畫一張表，每次呼叫一欄，欄位是「`len(queue)`、條件成不成立、走到哪一行、`queue` 變成什麼」。第二次呼叫的起點，要用第一次呼叫結束後的 `q`，不是原本的 `['a', 'b']`。

## 核對方式

先自己做完，再看答案。

<details>
<summary>答案</summary>

| | 呼叫前 `q` | `len(q) >= 3` | 回傳 | 呼叫後 `q` |
|---|---|---|---|---|
| 第 1 次（`'c'`） | `['a','b']` | `2 >= 3`，不成立 | `'ok'` | `['a','b','c']` |
| 第 2 次（`'d'`） | `['a','b','c']` | `3 >= 3`，成立 | `'full'` | `['a','b','c']` |

所以 `r1 == 'ok'`，`r2 == 'full'`，最後 `q == ['a','b','c']`。第 3 題的答案是 3 和 3。

</details>

核對時看這三點：

- 第二次的比較是 `3 >= 3`。如果你寫成 `2 >= 3`，代表你沒有帶上第一次呼叫留下的狀態。
- `'d'` 不在 `q` 裡。如果你把它放進去，檢查一下是不是漏看了第 3 行的提前返回。
- 函式裡沒有 `queue = ...`，只有 `queue.append(job)`，所以改的是呼叫者傳進來的同一個清單。第一次呼叫的結果才會留到第二次。
