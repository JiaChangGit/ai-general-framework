## 追程式的三個問題

1. **入口:** 從哪個函式、用什麼實際參數開始?
2. **條件:** 每個 `if` 在這組值下是真還是假?(先代入數字,再判斷)
3. **狀態:** 哪些東西被改了?改之前、改之後各是什麼?

追的時候不要憑直覺猜「大概會加進去」,每一步都先代入再判斷。

## 示範:`enqueue(['a'], 'b', 1)`

程式(`queue.py`):

```python
def enqueue(queue, job, capacity):
    if len(queue) >= capacity:   # 第 2 行
        return 'full'            # 第 3 行
    queue.append(job)            # 第 4 行
    return 'ok'                  # 第 5 行
```

**入口:** 呼叫 `enqueue` 時,`queue=['a']`、`job='b'`、`capacity=1`。

**條件:** 第 2 行要判斷 `len(queue) >= capacity`。

- 先代入:`len(['a'])` 是 1,所以是 `1 >= 1`。
- `>=` 包含相等,所以結果是 **True**。
- 容易看錯的地方是把它當成 `>`,那樣 `1 > 1` 就是 False,程式會走到下面。

**狀態:**

| 步驟 | 執行的行 | `queue` | 說明 |
|---|---|---|---|
| 進入函式 | — | `['a']` | 初始狀態 |
| 判斷條件 | 第 2 行 | `['a']` | `1 >= 1` 為 True,進入 `if` |
| 回傳 | 第 3 行 | `['a']` | `return 'full'`,函式在此結束 |

- 第 4、5 行**完全沒有執行**,因為 `return` 會直接離開函式。
- `append` 沒被呼叫,所以 `queue` 仍是 `['a']`,`'b'` 沒有進去。

**結果:** 回傳 `'full'`,`queue` 保持 `['a']`。

這個例子的重點是:**「條件為真」代表跳過後面的修改**。回傳值和狀態變化是兩件事,要分開記。

## 核對方式

先自己寫完,再對照下面的檢查點,不用跑程式:

- **你的表格有沒有「執行的行」這一欄?** 沒有逐行代入,只寫結論的話,很可能是猜的。
- **兩個分支只走一條。** 如果你寫的路徑同時經過第 3 行和第 4 行,就是漏看了 `return`。
- **一致性檢查:** 回傳 `'ok'` 時,`queue` 的長度必須剛好多 1。回傳 `'full'` 時,`queue` 必須和呼叫前一模一樣。你的答案如果違反這兩條,就哪裡追錯了。
