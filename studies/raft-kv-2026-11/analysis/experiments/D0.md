# D0 探測（2026-11-16）

目的（[SPEC.md](../SPEC.md) §3.2）：正式實驗之前，確認桌面 app 內附的 Claude Code CLI 能在 app 之外無頭執行，而且事件流裡有工具事件與用量。

**命令**：在 `artifacts/runs/s8-20261116/d0-read/`（只放一個 `hello.txt`）執行：

```bash
env -i HOME="$HOME" PATH="$PATH" LANG=C.UTF-8 TERM=xterm ANTHROPIC_BASE_URL=https://api.anthropic.com \
  ~/.claude/remote/ccd-cli/2.1.325-1ef04b37a794 -p "讀 hello.txt，原文照抄它的內容，不要做其他事。" \
  --model claude-haiku-5-5 --output-format stream-json --verbose --no-session-persistence \
  --permission-mode dontAsk --allowedTools Read --max-budget-usd 0.5
```

用 `env -i` 是刻意的：目前的環境裡有桌面 app 的訊息通道（`CLAUDE_CODE_MESSAGING_SOCKET`、`CLAUDE_CODE_MESSAGING_TOKEN`）和這個 session 的編號，
子行程若原樣繼承，可能把事件送回目前的 session，或和它的 session 紀錄衝突。

**結果**（原始事件流：`artifacts/runs/s8-20261116/d0-read.out.jsonl`，不在版本控制內）

- `init` 事件正常：模型 `claude-haiku-5-5`、23 個工具、24 個 skill、`apiKeySource: none`。
- 回覆 `Not logged in · Please run /login`，exit 1，用量 0 token、費用 0。桌面 app 的 session 是透過宿主取得認證，CLI 自己沒有登入資料。
- 意外的發現：在本專案的子目錄裡啟動，skill 清單包含本專案的六個 skill（`debug-root-cause`、`guide-learning`、`read-research`、`review-change`、`trace-code`、`write-bug-lesson`）。
  Claude Code 會往上層目錄找 `.claude/skills`，所以放在專案目錄底下的「隔離副本」其實不隔離；對照組必須放在專案目錄之外。
  另外 18 個是使用者層級的 skill（`deep-research`、`design` 等），兩組都會看到。

**結論**：第一項（能登入）不成立。依規格停下來，請使用者選擇做法。
