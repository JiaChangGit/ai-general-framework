# 從資料到文件、網頁與影音

需要把資料、文字或既有作品製成文件、網頁、圖片、漫畫、聲音、歌曲或影片時才讀。一般小修不必跑完整流程；這份參考不提供 renderer（把來源製成成品的程式）、素材庫或媒體服務。宿主已有適用 skill／工具就沿用，缺能力時說明具體缺項，不把草稿稱為成品。

## 先用一份內容，決定這次怎麼呈現

利用已提供的讀者、目的、材料、既定設定、格式與操作範圍，只追問會改變結果的未知。簡報、書面報告、互動網頁與三十秒影片的閱讀節奏不同，不把同一堆文字原封搬到每個版面；內容事實與已確認設定仍共用，轉檔不能重新編造。

- **有資料才下結論。** 先依 tools 指引確認讀取範圍與來源，數值由資料工具計算，再寫解釋。保留期間、單位、分母、缺值、來源位置和會影響結論的轉換；摘要不取代原始材料。聚焦的學術文獻比較用 `read-research`，普通網頁蒐集不硬套論文流程。
- **材料權利各自確認。** 程式授權、圖片／字型／聲音／音樂與資料來源條款分開；公開可讀、repo 的 MIT 標籤或工具的商用宣傳不代表每項素材可用。私人樣本留在授權位置，不因為要做作品就上傳整份文件、聊天或登入資料。
- **內容與表現分開改。** 保存足以重用的內容、素材來源及所需時間安排，沿用使用者已有檔案與命名；簡單一頁不必額外建 manifest。區分原作事實、已定設定、視聽提案與新增改編。改某頁、某段或配音時保留其他已確認內容；換工具則核對它真正接受的輸入格式。

資料整理、視覺設計與媒體合成可以分工，但需共用同一份確認內容、素材識別與時序，最後核對完整成果。不要因不同工具都成功，就推論它們之間沒有漏資料或錯位。

## 先驗最容易出錯的部分，再做完整輸出

已有作品或小修改直接處理相關範圍。新設計、長文或影音較複雜時，先做能暴露本次風險的小樣：最密集文字、長中文／識別字、代表版面，或含聲音與轉場的短片段。看實際渲染或播放結果後修正，方向已清楚且授權足夠就繼續，不固定要求使用者再核准一次，也不預設每件作品都要多模型評分。

視覺從用途與既有設計開始，選這次相關的少量參考；版型、字型、色彩與動效要幫讀者看懂關係。介面只改指定元件時保留其他設計，依本次變更檢查實際尺寸、重排、長中文、輸入法與載入／空白／失敗狀態。缺陷、可有理由例外的預設與純風格偏好分開，不靠黑名單、評分或裝飾數量判斷品質。

需要技術流程或架構圖時仍沿用[圖解指引](../diagrams/README.md)：AI 寫 Mermaid／必要的 draw.io 圖源，工具渲染；不為動畫效果自行補畫來源沒有的路徑。簡報的資料、版型、母片及編輯性另讀[簡報指引](../presentations/README.md)，不在這裡重建版型庫。

## 聲音、歌曲與影片

先辨認要歌詞、講稿、配樂、音效、完整演唱歌曲，還是含聲音的影片；文字任務完成文字即可。需要音訊成品時，依用途取得必要的語言、情緒、長度、段落、器樂／演唱及既定限制；使用者未指定且不影響核心時可提出合理方向，不丟一份音樂術語問卷。

歌詞、配樂、演唱、混音和影片合成是不同能力。先核對已可用工具的真實輸入、聲音／素材權利、輸出格式及費用範圍，不因能配音就宣稱能作曲，也不從聲音樣本推定已取得仿製同意。歌詞與曲式要尊重已定內容；小說改編保留人物、世界與敘事意圖，改動核心設定前提出具體提案，已授權自行發展的部分可直接創作。

需要結構化歌詞時，保留歌詞正文，再依選定工具標示主歌、副歌或橋段。例如 [Udio 的 guidance tags](https://help.udio.com/en/articles/11166249-level-up-your-creations-with-guidance-tags) 包含 `[Verse]`、`[Chorus]`、`[Bridge]`，但屬於引導，不是保證遵循的命令。標記依工具與版本確認，不為湊固定曲式改掉指定副歌；生成後實聽段落、歌詞遺漏／重複及時長，沒有音訊就只交付帶標記的草稿。

寫運鏡時分開主體動作與攝影機移動，交代方向及要顯露的內容；圖生影片沿用已確認畫面，描述接下來的動作。先驗一段代表鏡頭，需要時再組合運動。否定提示的支援依模型而異，例如 [Runway Gen-4 指南](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide) 要求以正向狀態描述固定鏡頭，而非堆疊「不要移動」；不將文字模型的禁令或某工具的參數當成通用影片語法。

將畫面、字幕、旁白、音樂與音效對齊同一個時間安排。已有配音時以實際音訊長度調整畫面，不以預估字數冒充精準時長；改文後重查相關段落與總長。程式動畫要能依選定 renderer 的契約定位時間並重現相同畫面，不能混用不同工具的秒數、影格或時間 API。長片先查看必要的首尾、轉場前後、密集字幕等代表影格，再播放相關片段；靜幀不足以證明節奏、接縫與音畫同步。

AI 產出內容、分鏡或工具接受的描述；渲染、合成、轉碼由工具完成，不展開音訊 samples 或影片影格資料進 context。保留可重用的來源與已完成片段，只重做需要修改的部分；這能減少重複工作，但未有完整 usage 就不宣稱節省多少 token 或費用。

## 各種格式分別驗收

只檢查本次要交付的格式與相關風險。檔案存在、工具 exit 0、能抽文字或一張漂亮截圖，都不足以證明整件成果可用。

| 成果 | 實際要核對的內容 |
|---|---|
| 文字／文獻整理 | 事實、來源、規範強度、作者語氣與已定設定；查找、判讀或創作各按本次目的完成 |
| PDF | 實際頁面、頁數、裁切／溢出、中文與字型、圖表／註腳；需要可搜尋或可讀順序時另檢查文字層，掃描圖不能冒充可選文字 |
| HTML／網頁 | 指定瀏覽器尺寸、互動、鍵盤與相關錯誤狀態；離線需求要斷網核對字型、素材、CDN 和腳本依賴，不靠已快取時能開啟判定 |
| PPTX／簡報 | 每頁內容、版面、講稿、格式轉換損失；文字、數據與節點各自的實際編輯性，沿用簡報指引 |
| 圖片／漫畫 | 實看人物肢體、表情、道具接觸與遮擋、場景及圖中文字，對照角色與畫風設定；刻意造型、對稱或光滑質感本身不是缺陷，不為去除 AI 味而統一改成另一種風格 |
| 聲音／歌曲 | 實際聆聽發音、歌詞、段落、節奏、音量、頭尾與總長；旁白和對話依語意檢查重音、情緒、停頓與輪替，不硬加猶豫、口頭禪或瑕疵。核對要求的格式／音軌，削波失真（音量超出可容納範圍）不能只看 metadata 排除 |
| 影片 | 尺寸、影格率、總長、音軌、畫面／字幕／聲音同步、轉場與實際可播放；跨鏡核對衣著、髮型、道具及位置，動作依既定世界規則連續。代表影格與播放觀察分開記錄，不從分鏡或 HTML 推成 MP4 |

沒辦法實際渲染、聆聽、播放或在收件端軟體驗證時，說明驗證到哪裡，不假稱完整通過。跨格式轉換需重查丟失的編輯性、互動、動畫、講稿與來源；不因一種格式通過就宣稱其他格式也通過。

外來 HTML 的腳本、瀏覽器 origin（網站來源）與本機 API 權限依 tools 指引核對；預覽器寫著 sandbox 不代表已有效隔離。分享／發布按 delivery 指引與當次授權處理，檢查隱藏內容、檔案屬性、嵌入資料及素材散布範圍。交付真正存在的檔案或帳號作品，清楚分開內容稿、可編輯來源、預覽與完成成品。

## 直接交代想要的結果

- 「用這幾篇論文說明這項方法在什麼條件下有效，再做成兩頁 PDF。只讀到摘要的就標示，不把同一研究的預印本與正式版算兩份。」
- 「這份資料做成可離線閱讀的 HTML；保留圖表數據和來源，先確認長中文表頭與窄畫面沒有裁掉內容。」
- 「依這份人物設定寫短篇，再改成三十秒影片；這次先交分鏡與講稿，不生成媒體、不上傳。」
- 「用我提供的歌詞做一分鐘歌曲，保留副歌；先核對現有工具能否演唱，再做含副歌的小樣，方向沿剛才的討論繼續。」

這些是代理的工作約定，不是新增媒體功能；已讀來源、採用理由與未採納的依賴記在框架維護者的研究紀錄，日常不用載入整份來源清單。
