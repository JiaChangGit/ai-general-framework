# 依這次問題選最少的能力

任務跨資料來源、需要外部服務，或工具選擇會改變成本與風險時才讀。先用目前可用且足以完成工作的能力；一般改字、單檔查找不需要路由報告。這份指引不會啟動服務、選模型或授予操作權限。

## 從材料與問題開始

| 要解決的問題 | 優先方法 | 何時才擴大 |
|---|---|---|
| 找字串、symbol、定義或引用 | `rg`、`git grep`、既有語言伺服器／程式索引 | 關係需要跨層追蹤才查可信索引，核對版本、未提交變更與涵蓋範圍；文字命中不是呼叫關係 |
| 依 ID、日期、狀態或明確欄位找資料 | 已連接資料來源的唯讀 SQL，參數化值、有限列數及必要欄位 | 確認時區、資料版本、權限與查詢成本；普通資料查詢不啟用資料庫變更審查 |
| 找文件原文、事實、頁碼或引用 | 已有文件工具、已定位原檔與來源摘錄 | 大量知識庫且已有授權入口時再選 RAGFlow 等檢索服務；回查原文，OCR／chunk 編號不冒充正式頁碼 |
| 跨文件關係、依賴與影響範圍 | 先取直接來源，整理有依據的節點與連線 | 確實需要跨文件或全局推理，且索引來源、版本、成本可接受時，再選 GraphRAG；缺邊不能推成沒有依賴 |
| 慢 SQL、執行計畫、重寫或索引建議 | `review-sql`；先讀已有 SQL、計畫、版本與測量 | PawSQL 的介面、啟用與授權適用才用；否則沿用原生計畫或審查已提供材料。`EXPLAIN ANALYZE` 會執行查詢，不能當成無副作用的預設 fallback |
| Schema、索引、權限或 migration 變更 | `review-sql` 搭配專案既有資料庫審查流程 | 有可用且適用的 Bytebase 就沿用；工具缺少時交付可審閱變更與驗證／回復步驟，沒有審查結果就不能自稱可部署 |
| 文件、簡報、圖像、歌曲、漫畫或影片 | 宿主已有的對應能力及本框架 writing／outputs／presentations 指引 | 實際交付格式欠缺時再找 renderer；文字稿、MIDI、樂譜、音訊、圖片與可播放影片各自驗收 |

RAGFlow 和 GraphRAG 是候選能力，不是固定順序的兩個必跑服務。直接來源已足夠就完成；不為了找一段原文建圖，也不為了畫關係圖重做已有解析。若選擇索引服務，先核對資料是否可送往該處、索引是否涵蓋這次版本，以及原文和引用是否仍可取得。

## 能力狀態要有範圍與證據

只在確實做過對應檢查時使用以下狀態，附時間、宿主、版本或端點範圍、所需功能和觀察。工具的存在、登入、服務健康、功能授權、資料存取與實際執行是不同檢查。

| 狀態 | 可支持它的觀察 |
|---|---|
| `available` | 本次所需介面、設定、授權與受限測試已確認可用；只對已驗功能成立 |
| `unavailable` | 此宿主未提供可呼叫入口，或明確的離線／缺失結果；不能由缺少 CLI 推成沒有 MCP／API 版本 |
| `misconfigured` | 已找到入口，但必要設定缺漏、驗證失敗或版本不相容，有實際錯誤可回查 |
| `license-limited` | 已核對當前啟用／方案，明確不包含本次所需功能或已達限制；不能把授權未知填成此狀態 |

未檢查項目另列為 `unverified_checks`，不要新增假狀態或補成成功。`doctor` 的 executable discovery 只能證明找到程式；列出 MCP schema 只能證明宿主暴露該入口。健康檢查成功也不能證明特定文件可讀、租戶權限正確，或 PawSQL 的 MCP、API、Community Edition 皆已可用。

能力檢查本身也有副作用。先讀可信設定與工具描述；不啟動未知 server、掃描全部內網或傳出真實資料來查它是否安全。憑證沿用已授權的原生登入、環境變數或 Secret Manager，不將值、連線字串或完整診斷包放進 skill。需要連線測試時限定目的地、功能與合成資料，失敗後保留原始錯誤及 fallback，不無限重試。

## 有必要時留下選擇理由

複雜或有副作用的任務可用短文字，或採下列最小 JSON 記錄；內容是計畫，不代表已呼叫工具：

```json
{
  "task_type": "sql_performance",
  "selected_tool": "review_supplied_plan",
  "reason": "已有慢查詢與計畫，可先判讀；外部分析介面尚未核對",
  "fallback": "request_native_explain_plan",
  "risk_level": "medium",
  "requires_bytebase_review": false,
  "required_review": "遵循專案既有資料庫審查，變更核准前不部署",
  "execution": "plan_only",
  "unverified_checks": ["PawSQL 本次介面與方案", "專案是否指定 Bytebase"]
}
```

`requires_bytebase_review` 只回答是否由 Bytebase 審查；false 不代表免審查。專案已指定 Bytebase 時不得改用另一條部署路徑繞過它。實際執行後另記工具、版本、資料範圍、退出碼／狀態、來源與限制，不能把待做計畫改稱成功。

PawSQL 或原生工具產出的重寫 SQL／索引都只是候選。先在適用的測試環境確認結果等價，保留前後計畫與實際效能、副作用及回復方式，再交專案既有流程審查；工具回報可用或建議有效，都不構成部署核准。

先看成果是否正確、是否越界及是否返工，再比較實際用量、延遲與新增的維護負擔。搜尋輸出較短不代表完整任務省 token；缺少 usage 就保留未知。工具或材料仍不足以完成時，交付能支持的結果、未驗項目及最小下一步，不靠更多服務或更多角色延長流程。
