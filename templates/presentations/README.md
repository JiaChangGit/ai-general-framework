# 簡報：內容交給 AI，排版與交付交給合適工具

製作、修改或匯出簡報時才讀這份指引。使用者提供主題、資料或作品連結，說明想拿到的結果即可；代理處理需要的命令與工具，不要求使用者學一套指令。本框架提供工作方式，沒有內建簡報服務、YAML 排版引擎或媒體平台，也不預裝相依套件。

## 先辨認要交付的成果

從現有對話和材料取得讀者、用途、頁數／時間、語言、範本與交付格式；只問會改變結果的未知。已指定八頁就包含封面在內共八頁；只改第三頁就保留其他頁。普通製作不需要載入追程式、除錯或研究等工程 skills；宿主已有適用的簡報 skill 時才按需使用。

| 使用者要什麼 | 選用方式與確認重點 |
|---|---|
| 帳號裡能繼續編輯的作品 | 先探索已連接工具，核對帳號、作品與讀寫能力。修改前讀取實際頁面及穩定的頁面 ID；保存後回查版本或內容。貼連結不代表工具已能讀寫，也不等於分享授權。 |
| 本地可編輯 PPTX | 優先沿用專案既有範本與排版工具；確認文字、表格、圖表、流程節點各能編輯到哪裡，不能只看副檔名。 |
| YAML → 既定版型 | YAML 是以縮排表達結構的文字資料。先讀**實際渲染器的 schema**（允許的欄位與結構）、版型與範例，再產出它接受的內容；也可沿用工具要求的 JSON／Markdown。不自創通用 YAML 規格、版型 ID 或不存在的命令。 |
| PDF、離線 HTML、含配音 MP4 | 分別核對可用匯出器及需要保留的效果。能輸出 PPTX 不表示也能輸出影片；網頁能播放不表示離線可用。 |

選工具依部署的 tools 指引查來源、版本、安全、資料流及原始回饋。缺少渲染器時，完成可用的內容稿、講稿或分鏡並具體指出缺項，不能稱為已產出 PPTX 或影片；安裝、新增連線與傳出資料仍依當次授權。局部修改能直接保存就直接做，不重做整份簡報。

## 內容、數字與論證

1. **先讀資料，再決定每頁的目的。** Excel／CSV 核對工作表、欄位、期間、單位、分母與缺值；Jira 等匯出資料要辨認狀態、完成定義、重複與父子工作，不能把所有列直接當成完成件數。保留能回查的來源位置與必要計算；不要把整份私人試算表塞進 context。
2. **標題依這頁實際內容決定。** 有證據的分析頁可寫結論，例如「稼動率連續四個月下降」；封面、定義與背景頁可以直接寫主題。不要為每頁硬湊洞察，也不把相關性寫成原因。
3. **缺什麼就明說。** 沒有目標值就寫「未提供目標值，無法判定是否達標」，不能補成 0、估計值或意義不明的 N/A。真實零值、未提供與不適用分開，保留來源本來的語意。計算沒有合理分母時不產出百分比。
4. **使用者決定主張。** AI 可先提出論證、標題與洞察；尚未確認的建議或推論在待審稿標成「AI 草稿，待確認」，並交代依據與缺項。已可查證的數值描述不必逐句貼標籤；會影響觀眾理解的未知直接留在頁面，不能只藏在講稿裡。

使用自然的台灣繁體中文，或遵循指定語言；刪掉沒有內容的口號與重複結論。每頁只放支撐該頁目的的內容，細節移到講稿或附錄，但不為縮短而刪掉關鍵限制。最終對外稿保留必要揭露，移除純製作過程的註記；未確認的主張則修正、移除或明確保留為假設。

## 版型、圖表與可編輯性

先看既有範本，分清「以此為設計範本」與「只取其中內容」。母片是統一字型、位置與版面的範本層，不是貼一張背景圖；工具要能處理實際 layout（版面配置），才可聲稱已套用母片。沒有需求就不先建數十種版型。

- **版面隨內容選：** 封面／章節、條列／比較、數字卡／表格、資料圖表通常足以起步；泳道、魚骨圖、地圖、製程管制圖等，確有資料與解讀需要再做，不為展示版型湊頁。一頁月報與投影拆頁版需要時由同一份確認內容衍生，保留各自頁數與閱讀需求。
- **數據圖保留資料：** 依比較、趨勢、分布或關係選圖，核對軸、單位、期間、分母及來源。需要後續改數據時用工具支援的原生圖表；截圖或 SVG 嵌入不等於原生可編輯圖表。
- **流程與架構沿用圖源路線：** 先讀相鄰的[圖解指引](../diagrams/README.md)，AI 寫 Mermaid，工具渲染；需要 draw.io 才選該路線。要在 PowerPoint 內逐一移動節點與連線時，須有可靠的原生物件轉換能力並實際檢查。沒有就保留 `.mmd`／`.drawio`，說明投影片內僅為圖片，不能把圖源可改稱為 PPTX 節點可改。
- **溢出先改內容或版面：** 在已定頁數、資訊完整性及可讀性間調整；必要拆頁會超出指定頁數時，先提出具體取捨。自動縮字只能在本次版型的可讀下限內使用，仍須渲染檢查，不能無限制縮到看不清。工具無法可靠容納時應停止該輸出並回報頁面與原因。
- **圖示與素材按需使用：** 優先沿用已有授權的素材與圖示；SVG 是向量格式，不代表其中每個部分在目標工具都能換色或拆開編輯。不要把 PNG 轉檔稱為可編輯向量，也不保證任意圖像生成結果可無損轉換。

固定版型加結構化內容可減少 AI 重複描述座標與排版的工作，但 YAML、地端模型或輸出較短都不代表已量測省 token 或品質。使用地端模型時仍確認上下文、工具與實際輸出能力，不保證所有模型效果相同。

## 講稿、配音、動畫與影片

需要時才加每頁講稿、重點框、放大或逐步出現效果，內容與頁面一致。文字講稿不等於已配音；配音須有實際音訊工具及允許使用的聲音，核對專有名詞發音、語速、音量、字幕與總時長。不要因有一段聲音樣本就假定已取得聲音仿製的同意。

用工具渲染、合成及轉碼，不由 AI 展開影格或音訊資料。匯出影片後核對實際可播放、頁面順序、配音同步、字幕和轉場；PDF 或靜態 PPTX 不自動保留動畫。離線 HTML 須測試斷網播放與素材是否自足，不能只看本機有快取時能開啟。外部服務的額度、付費或新增連線依當次授權處理，不永久綁定媒體供應商。

## 檢查、分享與交付

匯出成功後，實際渲染並看**每一頁**：核對內容覆蓋、頁數、範本、文字溢出、換行／字型替代、圖表標籤、來源與必要限制。自動檢查可找線索，不能代替逐頁觀察；能打開 ZIP 或抽出文字不代表版面正確。要求可編輯時，另核對相應文字、資料、節點等物件；未在 PowerPoint 檢查就不宣稱已在 PowerPoint 驗證。替代檢視器通過不保證收件人的軟體呈現相同。

公開或分享前，按實際風險檢查備註、評論、隱藏頁／物件、頁外內容、作者 metadata（檔案屬性）、嵌入工作簿／附件和外部連結。投影片看不到的資料仍可能隨檔案送出；不要為了隱私檢查任意清掉使用者要保留的講稿或圖表資料，必要時另做分享副本。清 metadata 或掃描通過都不能保證沒有私人資料。

先完成可審閱成果，再執行已獲授權的分享。分享不清楚時才確認對象與檢視、下載、共同編輯權限；「給同事看」不等於任何人都能編輯。已有明確授權就不重問，完成後核對實際權限與連結；沒有服務能力時不能捏造作品 URL。交付真正存在的作品或檔案，清楚區分草稿、已渲染簡報、已配音與已分享；僅說明會影響使用的缺項，不把檢查紀錄塞進投影片。

## 可以直接這樣交代 AI

- 「用這份 Excel 做八頁部門月報，包含封面，給主管看，要可改數據的 PPTX。沿用這份範本；沒有目標值就明說，不推測原因。」代理先讀需要的資料，選現有排版工具，產出並檢查；缺目標不妨礙呈現已有趨勢。
- 「這是 Jira 匯出的 CSV，做專案週報；完成的定義沿用我們專案設定。」代理先核對設定與狀態對照；對照未知且會改變統計時才問，不猜完成率。
- 「這份作品只把第三頁改成三欄，標題縮短，其他頁保留。」代理讀取實際頁面、修改及回查保存；不順便換母片、配音或公開。
- 「用我們現有的 YAML 版型工具做簡報，內容在這份文件。」代理找該工具的 schema 與版型，再寫內容並執行檢查；若不存在，具體說明缺少渲染器，不虛構產物。
- 「將已確認的小說分鏡做成三十秒投影片式影片，含字幕與講稿，這次先不配音、不上傳。」代理保留既定世界與人物；有工具就合成可播放成品，否則交代還缺哪項能力，不把分鏡稱為影片。

## 來源與適用範圍

2026-11-09 查閱一手文件；以下支持能力區別，不代表本框架已安裝或驗收這些工具，也不是固定推薦名單。實際使用先核對當前版本與原始回饋。

- [Pandoc 的 reference-doc](https://pandoc.org/MANUAL.html#option--reference-doc)與[講稿](https://pandoc.org/MANUAL.html#speaker-notes)：可沿用相容的 PPTX layout 和講稿；不保證任意範本完整保留。
- [Marp CLI](https://github.com/marp-team/marp-cli#convert-to-powerpoint-presentation-pptx)、[Slidev 匯出](https://sli.dev/guide/exporting)：預設 PPTX 可能是整頁圖片；兩者有各自的可編輯模式及限制，Slidev 的 SVG／Mermaid 仍以圖片輸出，不能僅從格式推斷可編輯性。
- [Microsoft 文件檢查](https://support.microsoft.com/en-us/office/collab-files/remove-hidden-data-and-personal-information-by-inspecting-documents-presentations-or-workbooks)：分享前須考慮隱藏資料與檔案屬性，檢查器亦有限制。

若日後確有反覆需要而補一個內容轉版型的薄 script，只處理已選工具欠缺的固定轉換與錯誤回報。YAML 用安全資料 loader 並驗 schema、大小與資源範圍，禁止內容指定可執行程式或任意 shell；[PyYAML 文件](https://pyyaml.org/wiki/PyYAMLDocumentation#loading-yaml)說明一般物件 loader 的風險，安全 loader 本身也不是沙箱。先有具體需求與驗證，再新增依賴，不預建通用版型引擎。
