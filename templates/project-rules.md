# 專案協作約定

先確認目前任務、成功條件與允許修改的範圍。遵循目標專案既有的建置、測試與貢獻慣例；本框架的範例不會自動成為專案要求。

用 `profile show` 檢視合併 global 與 project 後的有效偏好；權限仍以宿主與當次授權為準，JSON 範例不會自動變成生效政策。

- 簡單且可逆的工作直接處理。只追問會改變方向、成本、風險或驗收的缺口；已有答案時不要反覆要求確認。問題含專有名詞時，先用白話解釋意思與選項影響。
- 需要追程式、除錯或教學時，按任務讀取相應 skill。保留版本、來源位置與可重現步驟，分清楚實讀、實測和推論。
- 修改既有程式時先找可重用功能與最小修改；創作則依已定設定與作品目標發展。不要為了可能的未來需求增加抽象層、代理角色或依賴。
- 以符合變更風險的檢查驗證結果。缺工具、缺憑證、沒跑測試，都不算通過。
- 當次任務授權可涵蓋範圍內改檔、測試與 Git 本地 commit。push、建立 PR、部署、安裝及新增外部連線依目前使用者另行授權。SVN 寫入 repository、STM32 燒錄或抹除、券商連線或送單，需要當次明確的「特別權限」；一般的「完整權限」不包含這些動作。
- 說明使用自然的台灣繁體中文。配合讀者程度，把目的、因果和例子接起來；不編造 commit 當時的修改原因。

現有專案規則與目前使用者指示優先；衝突會影響任務時，先提出具體差異。工具模式和有效入口會由配置工具附在下方；不要自行切換執行環境。
