# 專案協作約定

先確認要做什麼、怎樣算做完、可以改哪裡。專案規則與使用者當次的指示優先；照專案既有的建置、測試與 commit 慣例。

- **對齊。** 簡單、可復原的事直接做；主動指出會改變結果的矛盾、漏項與誤解。要問的事在開始時一次問完，問之前先查專案與框架已有的東西；之後冒出來、安全可復原的照建議做並在回報說明，高風險或不可復原的才停下來問。每題寫給沒有背景的人看：是什麼、各選項的影響與代價、你的建議，名詞先用白話解釋。已回答的不再問。
- **skill。** 任務符合宿主列出的 skill 描述時，動手前用宿主的機制叫用（Claude Code 是 Skill 工具），不因自己做得到就跳過，也不另讀 `.agents/skills/` 的副本；宿主沒列出才讀 `SKILL.md`。
- **改程式。** 依序問：需要改嗎？專案、標準函式庫或已裝的套件有嗎？幾行改得完嗎？不為未來的需求加抽象層、代理角色或相依套件。
- **驗證。** 沒跑過、缺工具或缺憑證都不算通過；說「完成」或打 tag 前要拿得出證明的輸出。示範腳本、文件裡的命令、乾淨重建這類只跑過一次的檢查也要重跑。輸出被截斷時縮小範圍或續讀，不憑片段下結論；分清楚讀到的、跑過的與推論的。
- **工具。** 先用已有的工具（`agf` 的用法見 tools 指引）；技術圖寫 Mermaid 圖源；不憑欄位名稱猜二進位檔的 offset；需要外部能力先用宿主已連接的，不因宣傳就加裝。
- **續接。** 開多個子代理、跑長時間的命令，或用量可能不夠之前，把進度、決定和下一步寫進交接檔，每完成一個里程碑就更新；換模型或額度恢復後先讀它。
- **Git 與授權。** 本地 commit 在當次授權內可以做：用明確的路徑暫存，看過 `git diff --cached --stat` 才 commit；訊息寫為什麼改、怎麼驗證。push、PR、部署、安裝與新的外部連線要使用者另外授權；SVN 寫入、STM32 燒錄或抹除、券商連線或送單要當次明確的「特別權限」，一般的「完整權限」不算。
- **文字。** 用自然的台灣繁體中文，寫文件前先讀 writing 指引；不編數字，沒做的事不說做了。偏好用 `profile show` 查。
