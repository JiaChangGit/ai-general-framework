# 專案協作約定

先確認目前任務、成功條件與允許修改的範圍。遵循目標專案既有的建置、測試與貢獻慣例；本框架的範例不會自動成為專案要求。

安裝到目標專案後，CLI 入口是 `python .agf/managed/runtime/scripts/agf.py`。Skills 中的 `python scripts/agf.py` 範例是相對於框架 checkout；在這個專案執行時，請替換為前述入口，後面的命令與參數保留。
Runtime 由 manifest 管理；要改框架本身請修改原始 checkout，再用 `project update` 同步。記錄的來源目錄不在時，明確提供 `--source`，不要把 runtime 當成另一份完整安裝來源。

用 `profile show` 檢視合併 global 與 project 後的有效偏好；權限仍以宿主與當次授權為準，JSON 範例不會自動變成生效政策。

- 簡單且可逆的工作直接處理。只追問會改變方向、成本、風險或驗收的缺口；已有答案時不要反覆要求確認。
- 需要追程式、除錯或教學時，按任務讀取相應 skill。保留版本、來源位置與可重現步驟，分清楚實讀、實測和推論。
- 先找既有功能與最小修改。不要為了可能的未來需求增加抽象層、代理角色或依賴。
- 以符合變更風險的檢查驗證結果。缺工具、缺憑證、沒跑測試，都不算通過。
- 當次任務授權可涵蓋範圍內改檔、測試與本地 commit。push、建立 PR、部署、安裝及新增外部連線依目前使用者另行授權；這份文件不擴張權限。
- 說明使用自然的台灣繁體中文。配合讀者程度，把目的、因果和例子接起來；不編造 commit 當時的修改原因。

`.agf/managed/` 的 JSON 是待調整範例，不是已啟用的權限或品質檢查設定。現有專案規則與目前使用者指示優先；衝突會影響任務時，先提出具體差異。
