# Trace 與圖解的核對方式

讓圖和正文共同回答這次的問題，不強制每次填完整表。

| 需要確認的關係 | 至少保留的資訊 |
|---|---|
| 入口與 guard | 輸入範圍、guard 順序、第一個拒絕點、此前是否已有副作用 |
| 狀態與 ownership | 變更前後值、持有者、生命週期、移交及清理義務 |
| Callback 或跨程序 | 排程/發送者、接收者、關聯識別、後續執行上下文 |
| MMIO、DMA、裝置 | 位址空間、讀寫方向、可見性、完成與通知各自的證據 |
| 失敗或重試 | 已發生的部分效果、回傳值、可否重試、是否可能重複處理 |
| 圖的簡化 | 未畫出的路徑、圖中數值來自觀察還是假設、版本與來源 |

先給必要的系統位置，再放大一段路徑。圖前說明觀察對象，圖後解釋關鍵條件或下一個問題，避免逐格重述。

逐一核對箭頭與來源：函式名稱存在不代表此輸入會走到它；同時出現在 log 不代表因果；單一 backtrace 不代表跨 CPU 或非同步事件的全貌。Mermaid 能 render 只證明語法可處理，不能證明圖意正確。

輸出若供 GitHub 閱讀，優先採專案能顯示的 Mermaid 或既有圖格式；需要匯出、離線或精確版面時，再選獨立圖檔。圖中留有必要文字，不只靠顏色或互動解釋。
