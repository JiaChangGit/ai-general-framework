# 交接足夠資訊，保留責任邊界

先判斷委派是否能省時間或增加有意義的獨立檢查。角色代表要提供的能力與審查角度，不假裝真的取得某個部門、人員或外部服務的授權。

交接包含實際需要的內容：

- 要解決的問題、完成條件與範圍外事項。
- 版本、相關檔案、輸入、已確認結論及可定位的證據。
- 尚待決定的取捨、已排除的原因及不要重做的工作。
- 可讀／可寫的範圍、檔案責任、外部操作邊界、時間或用量限制。
- 預期交付形式、如何驗收及遇到哪種情況應停止並回報。

對可平行工作分配互不重疊的寫入責任。需要完整歷史才能判斷的任務不只給摘要；獨立評估則只給必要原始材料，避免把預期答案餵給審查者。

交接前去除不必要的私人資料與 secret。只有目標工具及資料政策允許時才跨供應商傳輸；模型或角色名稱不能擴張權限。

接收結果後由主責代理核對證據、整合衝突及完成驗收。多模型一致只是意見一致，不等於真實性證明。保存短而可續接的狀態即可，不把每次對話都複製成永久文件。
