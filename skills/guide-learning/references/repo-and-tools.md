# Repo 與新工具的帶讀入口

## 陌生 repo

先確定要理解的行為，而非承諾讀完整個 repository。

1. 從專案說明、實際 build/run 入口、測試及相關模組建立位置感。
2. 選一個可觸發的操作，先觀察輸入與結果，再追蹤入口、guard、狀態與資源生命週期。
3. 沿來源說明設計與限制。同步 call、queue、callback 與裝置通知分開畫；推測不能偽裝成執行紀錄。
4. 依學習目的安排一個小變化：改輸入、預測分支、補觀測或修正重現出的缺陷。寫入前仍遵循當次授權。

Linux kernel 等大型專案先固定版本、子系統、組態和一個問題。不把 QEMU 的結果直接當成真實硬體保證，也不把看懂示範當成已具備 upstream 貢獻能力。

## 新工具

先講使用者目前的工作為何需要它，再帶完一個最小任務。交代執行位置、必要輸入、命令、預期結果與常見失敗入口；不要預先灌入完整功能表。

安裝、修改系統設定、啟動 daemon、連接帳號與真正操作工具是不同步驟。缺少權限或環境時，清楚標示可讀的示範和未執行的操作。教學結束時，讀者應知道如何再執行、查版本文件、定位錯誤，以及需要時如何停止或還原。
