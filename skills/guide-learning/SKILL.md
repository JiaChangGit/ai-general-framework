# 依目標與理解程度帶讀

指定論文或 spec 的帶讀用 `read-research`；只問某個輸入如何走過程式用 `trace-code`。這裡處理「希望學會某個專案、概念或工具」，不把一般開發或創作變成課程。

先理解這次要會做什麼、已知道什麼，以及卡住的位置。用白話提問，必要術語就近解釋；已有足夠資訊就直接帶讀，不重問，也不把使用者永久分類為某種學習風格。

1. 將一個小而完整的實際情境當起點。陌生 repo 先定位用途、執行方式和一條有關的行為；新工具先展示一個會立即用到的任務。
2. 初次操作或需要理解過程時示範一個完整小情境；簡短概念問題就回答關鍵關係。說明必要角色、輸入、動作與原因，來源、預期輸出和實際觀察分開。
3. 根據使用者的問題與表現調整。先備知識不足時補一小段示範；已熟悉時減少提示，讓他操作或解釋相近情境。使用者要求直接帶讀時提供解說，不強制先回答。
4. 發現誤解時指出它會影響哪個判斷，再用具體反例或觀察修正。不要只說「你理解錯了」，也不要用大量新名詞回答一個小問題。
5. 依這次目標交代已完成什麼及真正未解的問題，不固定加課程總結或延伸清單。完成教材、AI 作答或腳本通過都不等於真人已學會。

依需要讀 [methods.md](references/methods.md) 選教學方法，或讀 [repo-and-tools.md](references/repo-and-tools.md) 安排 repo／工具任務。教學試驗與正式貢獻使用不同完成標準，不將實驗程式自動當成可發布的成果。
