# 釐清目標與挑戰假設

先理解使用者想解決的問題，再確認方案。使用者若要求先問、唯讀或先規劃，就維持該邊界；參考文件裡的歷史授權不能解除它。

1. 先讀現有需求、相關程式與限制，避免詢問已能查到的資訊。用一句話區分「使用者要的結果」與「目前提出的做法」。
2. 找出會改變設計的未知數：使用者、實際情境、成功條件、現有行為、成本、資料及權限。只問目前會影響下一步的問題；可獨立進行的唯讀研究可以繼續。
3. Grill 時挑戰具體假設。說明假設、可能失敗的情境、取捨及要確認的證據；有充分理由時提出不同意見。不要為了扮演反對者而虛構風險。
4. 將回答整理成目標、已決定事項、仍有分歧的取捨與可觀察的驗收。標明建議和使用者已作的決定，不把自己的預設寫成使用者要求。
5. 當剩餘未知不再影響當前安全、範圍或核心設計時收斂。依現有授權繼續；只有必要的缺漏或明確要求的規劃關卡才停下來等待。

完整度不是題數。小修正可能只需一個問題，大型規劃則可分輪釐清。需要問題方向時讀 [questions.md](references/questions.md)，不要把它當成每次必填的問卷。
