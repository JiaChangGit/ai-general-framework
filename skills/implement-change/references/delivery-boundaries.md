# 交付設定的變更邊界

先確認目標環境與既有機制，再編輯相符的來源。修改設定、實際執行部署與變更線上服務是不同操作；依本次授權判斷能進行哪一步。

- **CI/CD：** 找出事件、分支、工作權限、輸入與產物。檢查不受信任 PR 是否能接觸 secret、寫入 token 或可持續的 runner。使用最少必要權限，依專案政策固定外部 action 的版本或 commit；不要因為範例能跑就新增雲端權限。
- **Docker：** 確認 build context、`.dockerignore`、基底版本、執行身分與掛載。驗證 build 和執行時設定分開；不要讓憑證或私人資料進入 image layer。需要多階段建置時，說明它減少了什麼實際內容。
- **Kubernetes：** 先核對 context、namespace、workload、image 與目前狀態。檢查資源需求、探針、設定來源及 rollout/rollback。渲染或 dry-run 的結果不能當作正式環境已成功啟動。
- **Hooks：** 說清楚觸發事件、可能寫入的位置、失敗行為及如何停用。小而快、可預期的檢查才適合預設啟用；高成本或會改檔的操作不要藏在無法預期的事件裡。

檢查要對應風險。例如容器的語法檢查不能證明服務可連線；YAML 能解析不能證明叢集支援該 API；本機 hook 也不是可強制執行的安全邊界。
