# 規格閱讀的有效條件

先固定文件名稱、版本、errata、相關依賴及觀察對象。不要把不同年份、transport、command set 或平台實作混成同一份規則。

帶讀流程時可沿一個情境閱讀；單點查詢只取回答所需的條文，不必執行全部步驟：

1. 找角色、拓樸、物件及模式，確認規則是否適用。
2. 讀定義與規範用語，依這份文件自己的定義解讀 SHALL、SHOULD、MAY 等詞；不能假定所有規格都採用同一慣例。
3. 找有效條件、欄位屬性、狀態與動作，連同圖表、註腳、失敗路徑及 reset 行為核對。
4. 以明示的假設值走完一次正常情境，再加入本次相關的例外。查閱順序、規格規則、假設輸入、推導結果與實測各自標明。
5. 需要解釋適用範圍時，再改變一個前提比較結果。若來源未指定結果，就說未指定，不能擅自補成固定錯誤碼。

特別分清：支援能力、控制設定、目前狀態、歷史事件、協商結果與平台選擇。同名 bit 在不同模式未必有效；數值相等也不代表兩個狀態有相同意義。

公開材料只放有權發布的內容、必要短引與定位。保留義務、禁止、保留值和未定義語意，不能為讓中文順口而改變規範強度。
