# 2026-11-09 桌面代理的工具與交接驗證

先前的 CLI 原生工具對照受阻；使用者目前無法在 WSL 登入。本輪改在現有 Codex 桌面代理中，用隔離的合成材料繼續觀察工具行為。這是另一種宿主與另一個小樣本，不能和先前文字對照的 token 數字混算。

## 同材料的工具行為

使用目前模型 `gpt-6.1-terra` 的新代理，各任務對照一組未配置框架及一組配置框架的目錄；trace、debug、改寫各兩個新代理，交接產生與接手各兩個，共十個。兩組收到相同請求與材料，框架組依隔離目標的規則及所選 skill 工作。代理能使用本機命令；不連網、安裝、推送、部署或讀憑證。根據代理的命令與結果回報，以及下列本機重驗：

| 任務 | 觀察 |
|---|---|
| Trace | 兩組都定位 `r42` 的 `forbidden`、正確說明狀態未變，區分 log 與程式推論。框架組回報另讀專案規則及 `trace-code`。 |
| Debug | 兩組都重現 `busy` 後 `duplicate`，提交相同最小修法；各自的回歸測試通過。主驗證者另對兩份修正執行既有隱藏性質檢查，均通過，原重現程式未變。 |
| 中文改寫 | 兩組保留否定、重試條件、2 秒與一次、未知和單一錯字；框架組另明寫入列元件未知。此結果經人工核對，非真人閱讀理解實驗。 |
| 交接與新對話 | 兩組都保留有來源及範圍的長期語言偏好；接手者核對設定從 TTL 30 變成 20，算出到期 120、125 時無效，並將舊驗證視為歷史證據。主驗證者另重跑兩組現況，均在舊的 `expires_at == 130` 斷言失敗。 |

沒有追加使用者修正。框架組交接產生者回報，第一次以 .NET 寫檔因 PowerShell provider 路徑失敗，改用 `Set-Content` 後成功；這是一次代理內部重試，不是使用者返工。未取得完整代理工具事件或個別實際 token 用量，不能排除其他內部重試，也不能量化這組工具式任務的總 token 或成本；代理回報讀取 skill 不等同已證明宿主自動發現技能。這次沒有獨立盲評，不推論通用觸發率、效率或安全性。

兩組受測原始檔及結果放在本機 `.agf/qa/continue-verification-20261109/native-pairs/`；主驗證者的來源雜湊、修法一致性、隱藏案例及現況檢查記在同一 QA 目錄的 `native-pairs-audit.json`。代理最終答覆與命令則保留於本次對話的代理結果，並非另行擷取的完整工具事件紀錄。

## 不同模型的接手

取前一輪指定 `gpt-6.1-sol` 產生的交接與記憶文字，由測試者寫入隔離目錄，再把 TTL 改為 20。新的 `gpt-6.1-terra` 代理在另一個對話實際讀取來源並執行檢查：發現 policy 雜湊改變，到期為 120、125 時無效，舊檢查在仍要求 130 的第一個斷言失敗，舊通過結果不能證明現況。接手時 `observer.txt` 不在隔離目錄，代理明說無法核對其原件；沒有編造正式服務根因。主驗證者另重跑並核對來源雜湊。

這是一次同供應商、不同模型的交接；產生階段是受控文字輸出，由測試者建立檔案，不是產生模型自行寫檔。沒有驗證不同供應商或模型版本之間的普遍相容性，也沒有個別模型的完整 token 用量。

## WSL 補驗與剩餘範圍

沿用專案 QA 目錄中既有的 Linux Node `v24.22.1`，僅對測試子程序調整 PATH；WSL Python 3.14.4 完整 206 項 unittest 通過，沒有略過。先前因 Node 缺少而略過的 OpenCode plugin 語法與模擬宿主契約測試都實際通過；這仍不是在真 OpenCode 宿主載入的證據。首次補跑時臨時 PATH 遺漏 `rg`，使四項搜尋測試略過；已保留原結果並修正 PATH，第二次完整執行才得到零略過。原始輸出和執行資訊位於本機 `.agf/qa/continue-verification-20261109/`。

Linux 版 Codex CLI 已找到，但目前未登入；Windows CLI 的政策拒絕與 Core launch 錯誤仍未確認根因。使用者目前無法登入 WSL，因此沒有繞過 sandbox、複製認證或繼續重試該路徑。需要後續有可登入且能執行合成檔讀寫的 CLI，才能補做有原生工具軌跡與實際 usage 的成對試驗。不同供應商交接、真人理解及長期學習保留仍待實測。
