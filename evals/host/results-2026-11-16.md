# 2026-11-16 的觸發量測

用 [trigger.py](trigger.py) 在一個下游專案的評估裡跑兩輪，比較規則改寫前後。條件相同：Claude Code 2.1.325、受試模型 `claude-sonnet-5-5`、可用工具 `Read Grep Glob Skill`、`--permission-mode dontAsk`、每次預算上限 2 美元；
情境是 [scenarios.json](../scenarios.json) 的 `trace-without-lesson`、`learning-with-trace`、`flaky-repeat-evidence`、`cleaned-copy-is-not-original`（各自預期一個主要入口），以及 `object-authorization-and-model-output`、`presentation-priority-and-decision`（不需要 skill）。
框架組安裝 `trace-code`、`debug-root-cause`、`guide-learning`、`read-research`、`review-change`。兩輪都沒有拿掉 Bash（相當於現在的 `--allow-readonly-bash`）。每個條件只跑一次。

| | 改寫前：規則寫「按任務讀取相應 skill」 | 改寫後：宿主列出 skill 時用宿主的機制叫用 |
|---|---|---|
| Skill 工具的呼叫 | 0 | 2 |
| 自己讀 `.agents/skills` 副本的 `SKILL.md` | 3 | 0 |
| 該用的 4 個情境用到預期的 skill | 3（都是讀檔） | 1（經 Skill 工具） |
| 叫錯 skill | 0 | 1（`learning-with-trace` 叫了 `trace-code`） |
| 不該用的 2 個誤觸 | 0 | 0 |
| 6 次費用（CLI 估算） | 0.638 美元 | 0.603 美元 |
| 6 次 token 合計 | 670,167 | 574,969 |
| 第一回合比沒有框架時多出的 token | 約 2,193 | 約 2,250 |

沒有框架的對照組（改寫前那一輪）：0.457 美元、533,981 token。

讀法：改寫讓 skill 走宿主的機制，也不再讀給別的宿主用的副本；但模型叫用 skill 的次數變少，該用的 4 個只用到 1 個。這是每格一次的結果，可能是雜訊；要判斷措辭的好壞，得重複並交錯順序。
常駐部分（入口匯入的規則與 skill 描述）在改寫前約佔一次 session 費用的 9%；這次刪了四條重複指引的細節、也加了新句子，第一回合多出的 token 反而多了約 57 個。總 token 減少，是因為沒再讀 `SKILL.md`。
